# 里程碑

里程碑按 Harness 的可验收能力划分；T1—T5 是迁移场景的难度层级，L1—L3 是评测层次，三者不一一对应。阶段是验收重心，测试、评测数据和运行记录随开发持续积累。

本路线于 2026-10-18 确定，取舍见 [路线规划记录](worklog/2026-10-18-milestone-roadmap.md)。M0—M2 已在下述边界内验收；M3、M4 已有声明范围的工程交付，但总体验收仍有缺口；M5 尚未启动。

## 整体路线与交付边界

| 阶段 | 重点 | 停在这里能够交付什么 | 状态 |
| --- | --- | --- | --- |
| M0：离线验证基础 | 可复现的 rpcx T1/T2 场景与检查 | 夹具、规范、正确及错误候选、检查报告 | 已验收 |
| M1：单仓库 Agent 最小闭环 | 自主修改、修复、验证与提交 | 一次真实模型完成的单仓库补丁与证据 | 已验收，限受控场景 |
| M2：证据驱动的判定 | 有边界的完整性分析、语义检查、审核依据 | 增强的门禁、审核材料、L1 正反例与评测证据 | 已验收，限冻结场景及声明配置；真实 T3 自动成功未验收 |
| M3：多仓库批量闭环 | 异构输入、故障隔离、有界并发、批次预算与预留 | 故障隔离且受预算约束的批量交付、已划分开发与留出样本的 L2、初步效果与成本数据 | 收尾中；M3.1—M3.3 在声明范围验收，三仓批次及自动参考完成；实际人工复核、独立留出未完成，总体验收未通过 |
| M4：运行可靠性与恢复 | 中断恢复、重试、资源清理、离线审计 | 可恢复、可审计的批量系统；冻结的正式评测协议 | 与 M3 剩余验收并行；持久化窗口和客户端连接故障已补范围证据，正式评测冻结仍待，总体验收未通过 |
| M5：独立评测与整体验收 | 按冻结协议完成一轮正式评测 | 可复核的效果、成本、失败分布与局限报告 | 协议草案及开发分区的 v2 纳入/重算链路已具备；实际材料未齐，未冻结、未启动 |

M3 是最低项目交付点，但不代表全部项目目标完成：进程中断后的恢复与审计由 M4 验收，正式效果验收由 M5 完成。首版场景覆盖 T1/T2 和以默认超时变化为代表的 T3；其他 T3 变化、T4/T5 留作扩展，不作为首版全部实现的承诺。

项目保持单机执行，以候选补丁和审核材料为交付边界；不增加自动 PR、合并部署、分布式调度或复杂外部测试环境编排。

**目标与范围：**在现有独立验证器上，明确支持范围、证据充分性和判定依据。使用 demo-orders 的 T3 默认超时场景检验“编译和原有测试通过，仍可能违反迁移约束”；新增规范与场景版本，保留 M0/M1 输入和历史证据的可复现性。

交付有范围的迁移完整性分析、可信行为检查、审核报告、L1 构造任务集和独立 T3 参考标准。完整性分析只对声明支持的语言结构、构建配置和规则负责；遇到反射、动态封装、未覆盖构建配置等情况须记录缺口，不宣称证明任意 Go 仓库迁移完整。

**两类检查的区别：**完整性分析检查应迁移的位置和路径是否遗漏，以及哪些范围尚未覆盖；语义检查判断已修改路径的行为是否满足规范。例如，漏掉一个需要补超时的调用点属于完整性问题，虽然补了超时却覆盖调用方更短的 deadline 属于语义问题。二者互补，可以共用证据，不预先要求实现为两个独立模块。

| 可测验收条件 | 验证方式 |
| --- | --- |
| 正确候选、明确违规、证据不足分别得到预期判定 | 对 manifest 每个 case 断言检查状态、最终判定、规则标识、规范版本与条款；包含正例，不能全部标成 NeedsAttention |
| 判定引用的是实际候选的证据 | 核对候选摘要、代码位置、检查记录或日志引用；证据缺失或关联错误不得放行 |
| 发现编译和原有测试未覆盖的 T3 行为错误 | 构造超时语义错误候选，与正确候选、无法充分确定的候选对照；用独立参考标准核验 |
| 防止已知的虚假通过方式 | 注入测试删除、跳过、断言削弱、验证依据篡改及保护路径修改；按规则拒绝或标记证据不足，不一律禁止合理测试修改 |
| 分析与验证覆盖缺口可见 | 加入超出支持范围或必要检查未完成的样例，断言不被当作充分验证通过 |

执行状态、检查状态、候选质量判定分别记录。质量判定为 ReadyForReview、NeedsAttention、Rejected；Skipped 用于检查或任务未执行的状态，并记录原因，不作为第四种候选质量判定。必需检查被跳过不能算通过；确认不适用需有依据。基础设施故障保留执行错误，不能全部压成 NeedsAttention。

审核材料应形成“规范条款 → 相关修改 → 验证证据 → 未解决问题”的关联。门禁不能读取 case 的预期结果或独立参考答案来作判定。

**停止／调整信号：**已知假成功仍被放行，或依靠把所有候选标为 NeedsAttention 回避判断时，先修正门禁或收窄支持范围，不进入批量验收。

**验收边界：**第 9 节实施计划要求按固定协议记录一次真实实验，并未要求该次实验必须自动成功。M2 的能力验收不改变实验 04 的失败结论，不证明跨仓库适用性或降低人工审核成本。M3 先设计 Target/Run 与场景适配边界、L2 划分及调用前预算预留，再实现并发；同类 helper 缺口若反复阻碍开发集交付，回到有限摘要方案验证。

下一项依赖按[独立准备与接入交接](experiments/m5-evaluation-draft.md#独立准备与接入交接)推进：先约定实际角色并接收允许的元数据，再验证基线/参考与宿主接入。若接入过程需要调优开发侧打开源码或答案，应登记暴露并调整数据用途；不能把新增 Profile 开发视为天然不污染留出。原独立人员口径的实际安排尚未登记，准入说明完成不等于样本已准备或 M5 已启动；核对见[本步记录](worklog/2026-10-21-m5-intake-handoff.md)。

按用户后续建议，另行启动[全新 Agent 隔离准备试点](worklog/2026-10-21-agent-isolated-preparation.md)：不继承主对话，主调优流程仅接收来源/摘要/环境等元数据，完整材料由准备者单独处理。该方案能承担实际准备劳动，限制为同模型家族、共享文件系统的过程隔离；不将其标成独立人员留出或 M5 正式结果。原名额不回写，运行时 heldout 支持仍未开放。

首阶段已收到 [prepared_baseline 元数据回执](../scenarios/rpcx/l2/agent-preparation-v0.1.0.json)：准备者完成一个库级协议切片的禁网构建与所选 54 项测试/子测试，保留一个未执行的外部服务套件。主流程未读完整材料或独立重跑，该准备回执时点尚未评估应用业务代表性与 L2 准入；该回执不增加原效果分母，也不表示参考/Profile 已完成。

后续[隔离准入评审](../scenarios/rpcx/l2/agent-admission-v0.1.0.json)结论为 supplementary_only：应用/领域代表性与出站适配保真不符合预定判据，其他证据不足项保持未知。保留实际基线及原回执，停止该候选的 L2 业务参考/Profile 开发；此为准备适用性结论，不记作迁移失败或正式效果。下一应用样本先按这些判据确认选源适用性，再投入准备。

[应用样本重新选源](../scenarios/rpcx/l2/agent-application-selection-v0.1.0.json)确定一个来源及有限适配计划，记录当时的 selected_not_prepared：应用/原断言路径有静态依据，但依赖闭包及 B 尚未准备，构建测试未执行。该历史选源状态保持，后续准备结果另存，不将静态选源记作 L2 已准备或 M5 进展通过。

该来源的[有限应用基线](../scenarios/rpcx/l2/agent-application-baseline-v0.1.0.json)已 prepared_baseline：准备者实际禁网构建 20 包，原测试 11 项、新增检查 8 项、v1 SDK 测试 5 项完成事件通过；原测试单独运行观测到真实 SDK 派发，冻结材料不变且容器已回收。主流程只核对公开元数据，支持包测试、v2 SDK 及整仓不在本次验证范围；独立准入结果另存。

[应用基线准入评审](../scenarios/rpcx/l2/agent-application-admission-v0.1.0.json)已收束：新隔离评审 Agent 只读核对来源/基线、原断言路径及存量证据，六项必需条件均 supported，可进入参考标准准备。没有重跑测试或改变材料；当前尚无该样本的独立参考、可信 Profile 或 v2 迁移效果，完整默认期限真实到期等需在下一项建立。原人员留出与效果分母不改，M5 未冻结、未启动。

**目标与范围：**执行冻结协议下的一轮正式评测，包含预先规定的样本和重复次数。此时不是从零建设评测，也不是只运行一个样本。报告迁移效果、判定准确性、成本、失败原因及局限，保留失败、重试和未知结果。

| 可测验收条件 | 验证方式 |
| --- | --- |
| 实验遵守冻结协议 | 比对执行清单、版本与配置摘要；记录每次偏离及处理，不根据结果临时加预算重跑覆盖失败 |
| 结果能被他人复核 | 按说明重建环境、重算原始记录指标并复验已保存候选；不承诺再次调用模型生成完全相同的补丁 |
| 结论与样本规模、覆盖范围一致 | 同时报告分子分母、样本数、重复次数、未知结果和失败分布；区分开发集与留出集，不将小样本零错误解释为普遍无错误 |
| 项目能力和未完成项清楚 | 逐项核对 M2—M4 证据与 PROJECT 目标，记录未验证的业务语义、环境、模型波动及运行边界 |

**停止／调整信号：**环境复现成本超出预算时，可按明确规则缩小范围并形成新协议版本，保留旧结果与变更原因；不能静默删除失败样本或降低构建稳定性要求。看过结果并用于调试的样本转为开发样本，不能继续声称是未见留出。

## 贯穿各阶段的评测约定

| 层次 | 用途 | 开始时间 |
| --- | --- | --- |
| L1：构造任务 | 检查判定、保护、预算和故障处理机制；M0 用例作为起点 | M2 建立系统化任务集，后续持续增加 |
| L2：半真实异构仓库 | 观察不同封装和构建条件下的真实迁移、判定与成本 | M3 建立时划分开发与留出子集；开发子集持续评测，留出子集按 M5 协议启用 |
| L3：真实开源仓库 | 补充工程适用性证据 | 可选扩展，不阻塞首版验收 |

运行时门禁与独立离线评测分别维护依据。参考答案、隐藏测试和期望结果不进入 Agent 可见范围；离线评测不能只是重新执行同一套门禁。开发回归集可持续修正，留出样本从建立时就与调试样本分离。

M3 首次统计前确定分母、任务纳入规则、重试口径和每个 Target 的结果选取规则，M4 冻结正式版本。Run 级与 Target 级统计分开，不混用分子分母。至少报告：

- **有效自动成功率：**纳入评测的 Target 中，在约定预算及尝试规则内自动交付、门禁放行且独立评测通过的比例。人工修复、事后诊断和额外预算重跑单独列出，所有 Run 的成本仍须保留。
- **错误放行率：**被门禁判为 ReadyForReview 的候选中，独立离线评测确认违反规范的比例；同时列出错误数 k、放行数 A 和未知数 u。A=0 时不可计算，不能填 0%；u>0 时仅报告 [k/A, (k+u)/A] 的未知范围，不能把参考工具错误、缺证据或未复核直接算作候选错误，也不得宣称完整错误放行率。
- **需人工确认率：**报告 NeedsAttention 候选占已获得质量判定候选的比例；另按预定结果选取规则报告需人工确认的 Target 数及其占全部目标的比例。执行失败、未启动和无判定单独计数，避免隐藏分母。
- **成本与失败原因：**按 Target、Run 和 Campaign 汇总 Token、模型与工具次数、耗时及可核对的费用；未知用量不能当零成本。区分基线问题、模型/工具错误、预算耗尽、质量拒绝、环境故障和中断。

首个指标即使较差也如实报告。构造候选的门禁表现与真实模型生成任务的效果分开统计，不用精心挑选的反例比例推算实际业务错误放行率。
