# ADR-002：按宿主必需检查与绑定证据聚合质量判定

- 状态：Accepted
- 日期：2026-10-18
- 相关模块：internal/quality、rpcx/checks、rpcx/runner

## 背景与问题

旧验证器按六项 status 聚合，能区分拒绝与未知，但报告无法结构化关联条款、原因和实际材料。后续批量交付要复用同一套判定约束；缺少检查不能被空集合的“全部通过”放行，旧日志也不能用于证明另一个候选。

## 方案与取舍

继续将字段和聚合写在 rpcx 包最省初始改动，但把通用判定规则与 SDK 绑在一起；引入规则插件或 DSL 则提前增加注册与配置成本。采用小型 internal/quality 包：宿主提供固定 Policy、检查结果与材料，普通函数验证绑定后聚合；具体检查由场景包执行。接受额外材料落盘与摘要复核开销，暂不抽象存储接口。

仅记录证据路径无法发现过期或错候选材料；只验证摘要又不能说明使用了哪个规范和基线。因此证据同时包含相对路径、文件摘要以及规范/基线/候选摘要绑定。具体设计、代价及用例见 [M2.2 工作记录](../worklog/2026-10-18-m2-evidence-gate.md#13-m22证据与聚合的具体选择)。

## 决策与长期约束

- 必需集合由宿主 Policy 确定，不能从返回项、模型输出或用例 expected 推导。
- 缺项、解释或材料引用不足时保留缺口，不能 ReadyForReview。充分的明确违规证据优先 Rejected，同时保留其他未解决问题。
- 合法不适用需要宿主许可、跳过状态、理由及证据；当前 rpcx 六项均必需适用。
- 跨候选/规范/基线绑定、文件摘要或路径非法、重复 ID、结构契约错误使本次判定为空并返回 error；基础设施错误也不得包装成候选质量结果。
- 报告版本显式升级，新结构不追溯增强历史证据，也不把旧规范升级为 T3 验证。

## 验证与限制

机制测试检查缺项、未知、跳过、证据不足、fail 优先，以及错误绑定、篡改文件、路径越界和符号链接。真实 Evaluate 生成材料后重算判定、删除检查与篡改日志；旧五个 case 比较原状态与最终判定，并核对条款、原因和证据。

这些测试证明聚合与材料绑定，不证明检查生产者的业务判断必然正确。运行中的可信宿主仍是前提；哈希不是签名，也不防止宿主同时重写材料和索引。旧六项的语义与测试完整性限制仍然存在，T3 分析器和运行时探针需单独实现。

## 重新评估条件

出现第二套实际检查生产者后复核契约是否足够；证据规模或远程存储造成已测量的瓶颈时再考虑存储接口。分析器选型、测试语义等价及恶意生产代码防伪不由本决策替代。
