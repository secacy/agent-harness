# ADR-001：用共享执行层和短生命周期 Docker 容器运行检查

- 状态：Accepted
- 日期：2026-10-17
- 相关模块：internal/execution、repotools、rpcx/checks、rpcx/runner、cmd/harness

## 背景与问题

Agent 可以改动 Go 源码和测试。只限制文件工具的访问路径，无法约束构建或测试进程对宿主的访问；go_check 和最终 Evaluate 都需要明确的执行边界。模型客户端仍需访问服务，其凭证不能进入代码检查进程。

## 方案与取舍

继续使用宿主进程组只适用于可信夹具。把整个 Harness 放进容器会混合模型凭证、文件编辑和候选代码执行的权限。长期容器可复用缓存，但需要额外处理上轮残留进程、临时状态及跨验证污染。

本阶段选用每条检查命令一个容器。优点是状态和进程随命令结束销毁，Agent 检查和最终验证不共享可写缓存；代价是重复编译标准库、启动开销较大。出现真实性能瓶颈后再设计可证明清洁的缓存复用。

## 最终决策

共享 `execution.Executor` 接收宿主生成的命令、工作目录和只读目录。两个调用方决定检查内容，Local/Docker 后端负责进程、输出上限和回收。模型不能通过工具参数选择镜像、命令参数、资源限制或挂载位置。

命令入口默认 Docker，固定已在本地的镜像 ID，禁止任务期间拉取；本地后端需显式选择。代码和 SDK 只读挂载到容器内 `/workspace/<模块名>`，保留相邻 replace 布局。缓存、临时文件和构建输出在 1 GiB tmpfs，容器销毁后不保留；报告和探针注入由宿主负责，不挂载整个 Run。

使用非 root 用户、禁网、只读根文件系统、去除 capabilities、禁止提权及 CPU/内存/进程数限制。stdout/stderr 分别捕获、各限 4 MiB，超限终止命令。普通非零退出是检查结果，OOM、超限、启动或回收失败是执行错误，不发布质量判定。

容器预先命名并登记回收，不依赖 docker 客户端进程退出来判断容器结束。取消/超时后使用独立有界 context 执行强制删除；引擎故障或回收失败必须显式返回错误，不自动切换本地后端。

## 验证与限制

真实 Docker 已验证只读与可见范围、网络限制、资源设置、OOM、输出超限、取消/超时及容器删除；可控模型的完整迁移和 CLI 默认后端也通过。详细条件见 [执行记录](../worklog/2026-10-17-docker-execution.md)。

容器依赖可信镜像和容器引擎，不是虚拟机级安全边界；没有声称可抵御内核或引擎漏洞。引擎中断、宿主崩溃后遗留容器的自动扫描清理尚未实现。当前仅支持本地 Docker 引擎的文件挂载，远程引擎没有路径上传能力。不能将资源隔离测试视为迁移语义正确性或真实模型成功率的证据。
