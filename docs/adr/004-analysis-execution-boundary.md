# ADR-004：类型加载与查询在执行后端内完成

- 状态：Accepted
- 日期：2026-10-18
- 相关模块：scenarios/rpcx/analysis
- 依据：[工作记录](../worklog/2026-10-18-m2-evidence-gate.md#15-m23隔离类型加载与有限边界分析)

## 背景与问题

ADR-003 选择类型信息辅助迁移分析。生产执行使用一次性 Linux 容器，源码只读，缓存随命令回收。宿主可能使用 macOS，无法直接读取容器中 go list 返回的导出文件路径；宿主重新加载源码也可能选择不同的文件或编译配置。

## 方案与选择依据

导出缓存搬回宿主，可以复用本地查询原型，但需要增加材料搬运、路径映射、导出格式及工具链一致性处理；现有 Executor 只返回有界输出，不提供缓存导出。扩大可写挂载会改变已接受的执行边界。

在宿主另跑加载可减少容器侧程序，但默认宿主平台与实际验证平台不同，需要重建交叉配置和依赖条件。单独声明 GOOS 也不能省去这些一致性验证。

因此选择在同一执行命令中加载包并完成类型查询，只返回结构化事实。导出文件始终由产生它的环境消费，宿主无需解释其缓存路径；延续现有只读挂载与一次性回收能力。接受编译可信程序和依赖的开销、跨进程协议及其校验成本。

当前用标准库与 go list 已满足固定 SDK 夹具的加载需求，未引入额外包加载库。若后续复杂依赖需要 go/packages 等库，可在相同执行边界内比较替换，不要求宿主消费导出数据。

## 决策与约束

可信分析程序由宿主嵌入和写入单独只读根，与候选生产代码、SDK 分开挂载。程序不执行候选 init 或测试；包选择、编译、类型查询使用相同环境和临时缓存，记录工具链、GOOS、GOARCH、cgo 和 tag。

结果绑定整个模块与显式 SDK 根的文件摘要、分析程序材料摘要、实际源码位置和内容摘要。宿主检查协议、配置、源码路径、必需集合及前后输入不变，保存实际命令和日志。输入变化使可用结果失效，并撤回已发布的分析文件，保留原始输出。

加载非零退出保存 load_failed、退出码和诊断，不能单凭它宣称候选错误；后续结合独立构建及执行结果分类。执行或协议错误不提供可用分析结论。分析完成与质量通过分别表示。

## 验证与限制

本地与真实 Docker 均验证冻结候选的 SDK 身份及直接超时边界；Docker 对照包括错误常量、默认配置未激活文件、显式 tag 下的额外调用和容器回收。协议篡改、输入变化、输出路径重叠及取消有机制测试，实际结果见工作记录。

目前只覆盖夹具的离线普通 Go 包，cgo 关闭；不承诺任意依赖、vendor、overlay 或工具链版本都受支持。类型身份及结构关系不证明业务行为，仍须组合可信探针和测试完整性证据。哈希绑定依赖可信宿主和分析程序，不提供对抗任意宿主篡改的保证。

## 重新评估条件

当冷编译成本成为实测瓶颈，或复杂仓库暴露当前加载方式的不足时，比较可信程序预编译、加载库或受控缓存方案；每项优化都需保持构建配置、输入绑定与隔离边界可验证。
