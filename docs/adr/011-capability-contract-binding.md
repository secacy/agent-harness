# ADR-011：评测能力兼容性与查询原文身份分开绑定

- 状态：Accepted（2026-10-23，模拟服务及离线兼容性范围）。
- 日期：2026-10-23。
- 相关模块：L2 Protocol/Enrollment/离线汇总、batch 能力查询与预算 Profile。
- 依据：[设计与验证记录](../worklog/2026-10-23-capability-contract.md)。

## 背景与选择

[GHCLI 唯一启动](../experiments/2026-10-23-ghcli-dev-real-model-01.md)中，Models 仅新增未使用的 Anthropic Messages 元数据，整份响应摘要变化却阻断了 Chat Completions 实验。原文摘要适合标识证据，作为全部运行兼容性条件则会受无关变动影响。

持续更新期望原文只能解决单次启动，下一次附加元数据仍会阻断。直接更改所有协议的设置摘要会改变历史准入和复验语义。因此选择新协议显式启用按所用能力匹配，并继续保留实际原文身份；接受维护两种绑定语义以及对新策略追加原文核对的成本。

## 决策

schema 2 Protocol 可显式指定 `capability_binding: "model-contract-v1"`。新策略的设置摘要在原有动态 ID/查询时间之外，只额外排除 Profile.SourceSHA256。模型、端点、供应商、上下文上限、请求输出限制、输入、额度、并发、时限及资源设置继续精确匹配，不采用“上限更大就兼容”。所用模型唯一性、文本能力和可支持的请求输出仍须本次实际查询验证。

缺省策略及旧 PlanSettingsSHA256 函数保持原文身份比较；旧协议不升级、不回写。未知策略在本地检查拒绝；新策略需要理解该字段的新工具。与请求模式或计量有关的新能力应明确加入将来的契约版本，不能将它静默归为无关字段。

实际 plan.json 不剔除查询时间或来源摘要，账本继续绑定实际 Profile；Manifest 绑定实际计划全字节。新策略离线汇总要求实际 models.json 与计划来源摘要相符、capabilities.json 的 Profile 与实际计划相同，登记原文副本并复核读取稳定性。设置比较忽略某个来源差异，不授予替换已执行轮次原文的权利。

## 验证与限制

localhost 模拟服务已走通 CLI、调用前预算预留、Runner 与离线汇总：无关附加字段和排版变化可准入，关键能力变化或缺失零生成，当前原文身份在请求前已保存并进入账本。旧四任务汇总重算的计数、指标、成本、逐任务结论及协议均保持原样；原文缺失/篡改和 Profile 冲突被拒绝。相关竞态测试通过，详见工作记录。

本决策不认证供应商内部实现、同名模型权重、计费行为或历史真实性；解析供应商声明仍依赖可信宿主，材料链没有签名。新模式也不提供新增模型调用授权，不自动重试旧失败实验。真实新生成尚未执行，旧指标不改变。

## 重新评估条件

新增 thinking、服务端工具、流式用量或其他影响计量/请求语义的能力时重评字段集合；若同名模型语义稳定性成为验收要求，应取得可固定的服务版本，而非仅依赖别名和 Token 上限。
