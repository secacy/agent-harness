# ADR-005：评测数据与验收工具独立版本化

- 状态：Accepted
- 日期：2026-10-19
- 相关模块：rpcx T3 场景验收、L1 独立交叉验收
- 依据：[工作记录第 24 节](../worklog/2026-10-18-m2-evidence-gate.md#24-冻结数据与验收工具的版本边界)

## 背景与问题

旧 T3 冻结清单同时包含夹具、规范、补丁、参考标准、根说明及验收源码。模块路径调整改变四份工具源码，默认验收因冻结校验失败。工具需要修复和演进，而正式引用的数据身份应可长期追溯。

## 方案与取舍

原地重签旧清单会让同一版本对应不同字节；仅还原旧模块导入又无法使用当前模块编译。排除旧清单的源码条目则会默默改变原清单含义。因此采用新的数据发布与独立工具记录，保留旧完整快照。接受一份约 180 KiB 的历史副本以及显式维护数据、规范和工具身份的成本，使浅克隆或源码包也能离线复核旧材料。

## 决策

冻结对象为运行实际消费的数据：夹具、规范、补丁/预期和独立参考。活动验收源码置于数据目录外，普通根说明可独立维护。数据变更发布新版本，历史清单、字节和报告保留；工具变更保存实际工具材料与摘要，并创建新运行，不能改写旧结果。

T3 数据版本 rpcx-t3-data-v1 与迁移规范 v0.2.0 分别记录。数据根完整扫描，清单不能通过漏列额外文件缩小覆盖；未知格式、非普通文件和越界内容不进入执行。T3 与 L1 共用同一读取范围，执行前后核对实际数据，正式模式必须冻结匹配。

报告分别保存数据版本/摘要、工具摘要和工具材料。工具摘要只覆盖报告列出的源码，包括共享数据读取器；完整执行环境仍需代码版本、工具链和后端配置，不能将局部工具摘要称为整个 Harness 的摘要。历史报告使用原 schema，新数据边界的 T3/L1 报告使用 schema_version=2。

## 验证与限制

机制测试核对旧完整快照及新数据投影，验证数据篡改拒绝和可维护说明的边界。完整正式验收结果记在上述工作记录。可信宿主维护清单，这些摘要用于身份绑定和复核，不是抵御任意宿主重签的签名系统。

旧版完整快照放在 _archive 下，其原验收源码属于历史证据。复现旧工具需使用原模块及环境条件；当前工具执行旧数据所产生的是一份新运行，不能借此宣称旧工具已重验。

## 重新评估条件

当数据量使逐版本复制不可接受，或评测需在脱离 Git 的环境分发时，比较内容寻址存储或独立数据包；保持版本身份、精确清单、实际工具材料和输入不变检查。
