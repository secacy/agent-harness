# ADR-010：Docker 创建前记录归属，未知创建不以缺失放行

- 状态：Accepted（受控故障与真实 Docker 单代恢复范围）。
- 日期：2026-10-21。
- 相关工作：[M4.3](../worklog/2026-10-21-m4-resource-ownership.md)。

## 背景

宿主 SIGKILL 后 defer 无法回收容器。公共标签不区分 Run；仅记录成功响应的 ID 无法覆盖创建响应丢失。服务端可能在一次“查不到”之后才完成创建，固定等待时长无法提供一般证明。

## 决定

新 Campaign 首次计划可选冻结 docker-intent-v1、Docker context 和 engine ID，接纳任务前发布注册表。每个 Docker 命令在创建前持久化唯一名称、Campaign/Plan/Target/Run、镜像与挂载、请求参数摘要，并将意图摘要及注册表摘要写入容器标签。每意图仅发一次 create，不自动重试。

清理持原 Campaign 写锁，先审计静态归属，再核对 engine、名称、完整 ID、意图标签、镜像及只读挂载，仅按完整 ID 删除。查询注册表标签只用于发现未登记资源，不能据此猜测后删除。创建完成见证先于删除保存，确认不存在后保存移除见证；重复清理不改已发布记录。运行时任一回收结果未知会关闭本代后续命令准入，在途命令继续各自收尾。

dispatch 已发布、没有创建完成见证且查不到容器时，保留未知并阻止恢复。重启、换锁、重试清理或等待一段时间都不能解除。之后找到并认证实际容器时，才可补完成见证并精确回收。

运维资源记录会随新 Run 增长，不进入不可变迁移检查点的来源 pin；每次审计独立读取并复核。只读审计只证明记录关系，恢复必须重新做实时检查。旧批次不可补建协议取得恢复权限。

## 影响与边界

接受少量 fsync 与 Docker 查询开销，也接受“实际没有资源但无法证明”的阻塞；这优先保护其他 Run 和恢复安全。若未知创建频繁阻碍交付，再比较创建代理或服务端可核实的请求完成协议，不添加 assume-clean。依赖可信本机 Docker CLI/daemon、单次 create 与协作写锁，不抵抗恶意宿主或复制批次并行消费。清理不退款、不终止供应商推理、不授予模型调用权限。连续多代恢复仍另行设计。
