# Coding Agent Harness：项目定位

更新：2026-10-31。项目转向**有数据支撑的 Agent 运行时基础设施，以代码迁移为验证负载**。当前需求、非目标与验收标准以[需求与 TODO](REQUIREMENTS.md)为准，进度见[里程碑](MILESTONES.md)。

## 要解决的问题

长任务会经历多轮模型调用、文件修改和命令执行。中断之后能否保留已完成工作、预算是否重复结算、失败能否定位，以及独立门禁是否值得其成本，都需要运行记录与对照实验来回答。

rpcx v1 → v2 迁移保留为验证负载：接口变化之外还包含默认超时等行为变化，能覆盖编译通过但行为错误的候选。现有 Goddd、Translation、Workouts、GHCLI 是已见开发样本；不把这些样本上的定制证明推广成任意仓库能力。原“SDK 升级期限与数十个业务仓库”的叙述是场景设定，不是生产部署或规模数据。

## 两条主线与成功标准

| 主线 | 需要回答的问题 | 验收数据 |
| --- | --- | --- |
| 运行时可靠性 | 能否追踪和回放一次运行？中断后能恢复多少工作？隔离边界是否生效？ | trace 对账、故障注入恢复成功率、相对整代重跑的 token/时间/成本节省、越权用例结果 |
| 评测与验证 | 完整系统相对基础 Agent 有何收益？门禁减少多少错误放行？能否适用于未见输入？ | 三组重复实验的自动成功率、错误放行率、误拒率与成本；3–5 个未见仓库的冻结评测及接入成本 |

数字比功能数量重要。无收益、负收益和未知都如实保留；不按结果调参、补跑或改写旧指标。真值必须独立于被测门禁，人工复核与助手复核分开记录。指标分母、未知值和计费边界见[需求第 4–7 节](REQUIREMENTS.md)。

## 通用运行时与领域逻辑

| 边界 | 现有职责 | 本轮方向 |
| --- | --- | --- |
| `internal/agent`、`repotools`、`deepseek` | Agent 循环、受限文件/命令工具、模型适配 | P0 记录模型/工具轨迹，P2 持久化 step 状态 |
| `internal/campaign`、`budget`、`execution` | 有界调度、调用前预留/结算、Docker 执行与资源归属 | 复用已有机制，补充可核对的 trace、成本及故障证据 |
| `internal/audit`、`recovery` | 只读审计、不可变批次恢复检查点、受控单代整 Run 重跑 | 保留历史协议，新增 step 恢复契约；审计不冒充回放 |
| `scenarios/rpcx` | 任务输入、迁移规范、可信 Profile、领域门禁与独立参考 | 作为实验负载；暂停继续扩大规则和支持写法 |
| `cmd/harness` | 已有单任务、batch、audit 入口 | replay、归因统计和 resume 仅为计划，验收后才加入命令文档 |

生成与判定保持分离，Agent 不能修改可信规范、验收材料或独立参考。评测中的 A/B 无门禁条件只改变实验策略，不放松隔离、输入保护和硬预算，不改变生产默认门禁。

## 范围与停止条件

当前范围是 trace 与回放、基线与消融、检查点恢复、未见样本评测、有限沙箱越权切片和复现文档。默认顺序 P0 → P1 → P2 → P3；P0 是 P1/P2 的共同前提。每阶段达到验收标准就停止该阶段扩展。

不做新的 rpcx 门禁形式扩展、完整 K8s、第二沙箱后端、CLI/SKILLS 产品化、系统化上下文工程、IDE 集成或自动 PR。必要的 replay/resume 命令属于实验与复现入口，不等于 CLI 产品化。P3 暴露的门禁正确性缺陷可另作修复，但不回写冻结实验。

P0–P3 达标后停止功能扩展，转入 P5。P4 只覆盖列明的限额、出口和越权用例；与发布停止条件的衔接及尚待明确的硬门槛见[需求第 12 节](REQUIREMENTS.md)。最终交付仍以补丁、运行证据和报告为边界，不自动合并或部署。

## 当前基础与证据边界

现有工程版已实现单机批次、预算、Docker 隔离、领域门禁、审计与受控整代重跑。统一 trace、模型响应驱动的 Run 回放、step resume 及本版重复对照尚未验收。历史四任务评测曾得到有效自动成功 1/4、错误放行 0/1，后续不同配置观察另存；这些结果不证明稳定收益或泛化。

[交付说明](DELIVERY.md)记录已有能力与原结果，[离线演示](DEMO.md)复验历史归档，[需求第 13 节](REQUIREMENTS.md)列出源码核对与具体缺口。旧 M0–M5 保留历史验收状态，不因切换路线而宣布完成。

## 核心术语

| 术语 | 含义 |
| --- | --- |
| Campaign | 一个批次，包含多个 Target |
| Target | 批次内一个固定仓库任务，可关联多个 Run |
| Run | 一次执行尝试；执行终态与候选质量分别记录 |
| step（新需求） | 一次模型请求及其整批工具调用/结果；最终回复也是一步 |
| T1–T5 / L1–L3 | 历史迁移难度 / 评测层次，不是当前 P0–P5 阶段 |
