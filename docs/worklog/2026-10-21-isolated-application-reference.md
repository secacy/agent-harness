## 目标与交付范围

准入说明该有限业务切片适合继续准备，不提供 v2 正确性的判断标准。本步实际制作可重放的独立行为参考、一个手工正确 v2 对照及三个单错反例，并验证参考能够接受正确行为、指出已知违反。原 v1 B 和正确 v2 均需实际等待默认 30 秒到期，补齐之前仅有期限值及较短父期限观测的限制。

完整新规范、参考源码、正确/错误补丁、日志及复现脚本由隔离侧保管在 `runs/m5-application-reference-01/private`；主流程只收公开身份、条件状态、计数及通用限制。结果属于手工对照的参考校准，不是模型自主迁移，也不增加原实验分母。本步不接入可信 Profile、运行时 heldout、正式协议或付费模型。

## 方案取舍与固定契约

优先级是行为参考与现有运行时门禁相互独立、输入不被改写及真实到期可观察，其次才是准备速度和复用程度。

| 方案 | 当前任务下的得失 | 选择 |
| --- | --- | --- |
| 复用准备阶段新增探针或旧场景门禁 | 接入快，但会把同一套检查当成独立依据，无法暴露共同遗漏 | 不用于本轮参考实现 |
| 新隔离实现者按契约与 U/B 业务编写行为参考 | 保留与准备者、门禁及主调优上下文的边界，可接受等价生产实现；需要手工正确/错误对照来检验参考本身 | 采用；同模型家族、共享文件系统及同一参考作者编写对照的限制仍保留 |
| 全仓与真实网络评测 | 覆盖更广，但超出已准入有限切片、禁网依赖和进程内 SDK 范围 | 不纳入本步；范围不完整需明确披露 |

在启动实现前固定任务 `runs/m5-application-reference-01/public/assignment.json`，SHA-256 为 814bd0b36561de72fb01c32b16e022bf74c3589b360465fceaf3d40811f2e3a5。新实现者 `/root/application_reference_author` 使用 fork_turns=none，不继承主调优、准备者或评审者会话，也不联系其实现者。它只读取指定的 U/B、来源/依赖材料及共用 SDK；不读取原新增探针或其他场景参考/门禁实现。私有规范和外部 expected 清单须先于执行固定，参考材料在首次执行前冻结；修正需保存旧修订和失败，不反向调阈值放过错误对照。

行为参考接受候选与可信输入身份，不以正确补丁的 AST、对照 ID、expected、原 gate verdict 或 Agent 自述代替观测。原测试在单独副本运行，独立参考生产副本剥离候选测试。原断言和候选代码完整性另有材料绑定，不能把生产副本的行为通过当成原测试保留证明。

## 验收条件与执行顺序

本轮固定八组条件：原业务行为、v2 SDK 契约、请求上下文、逐调用超时、真实默认到期、错误及资源释放、参考独立性、证据绑定。具体可执行断言由隔离实现者先按 SDK 和既有业务固定，主流程不读取测试名、实现或答案。

| 输入/对照 | 预期及必要观察 |
| --- | --- |
| 原 v1 B | 不改基线；原行为通过，实际默认到期；v2 接口条件明确不适用 |
| 手工正确 v2 | 原断言保留，实际生产路径使用 ctx-first v2 Call；继承父上下文、较短期限/取消、每次调用 30 秒上限、错误和资源释放满足契约；实际等待默认到期 |
| 遗漏超时 v2 | 能由逐调用超时条件指出违反；原测试实际结果仍单列 |
| Background 兜底 v2 | 能由请求上下文条件指出违反，不能仅凭编译或普通业务测试通过放行 |
| 吞错 v2 | 能由错误传播或原控制流程检查指出违反 |

实际到期必须经真实应用生产路径、真实 SDK 并等待约 30 秒；仅检查 Deadline、改 SDK 常量、缩短计时或伪造时钟均不满足。执行前固定合理时间容差，外部 watchdog 只用于终止异常等待，命令超时不能自动当作确认的语义失败。反例先被快速条件明确拒绝时，可以不执行无意义的长检查，但未执行项目不算通过。

先核对固定输入，写规范和 expected，再制作/冻结参考与四个 v2 对照，最后执行原测试和独立参考并按 expected 外部比对。所有执行使用已有固定镜像，禁网、只读根文件系统、2 CPU、2 GiB、128 PID、去全部 capabilities 与 no-new-privileges；复用已有有校验和的依赖缓存且只读挂载。源码、SDK 和旧证据只读，缓存/日志放新输出，精确标识并清理自建容器。

主动实现预算约 25 分钟，接受真实 partial/blocked 结果，不换来源或改旧准入。需要新增依赖、突破既定语义范围或基线不再满足条件时停下记录原因；本步不通过修改根 Harness 来消除样本缺口。

## 结果解释

参考逐项使用 pass/fail/inconclusive，外部校准另比对预期。原测试、参考检查和 SDK 测试若执行则分列，父测试/子例与运行次数不混算。所有条件、代码/材料身份、命令及日志摘要、时间、失败修订和清理状态均需保留；设施失败与确认违规区分。

完成本步只能说明该范围的参考及已知正反例得到验证。没有自动证明通用候选完整性、严格人员留出独立性或新模型效果；后续可信 Profile 与正式协议纳入仍需实际设计和验证，M5 当前未冻结、未启动。
