# P0：Trace 与离线回放的设计取舍

需求来源：[P0](../REQUIREMENTS.md#p0trace-与离线回放)。实际验收与历史材料清单见[离线验收报告](../experiments/2026-10-31-p0-offline-replay.md)。本文件集中说明跨模块选择；当前进度只在[开发入口](../README.md)维护。

## 选择与理由

在模型/工具适配器外包装，可以记录普通交互，但看不到 Loop 自行拒绝的未知工具、工具整批额度不足及取消检查。首版在生产 Loop 中直接记录调用与控制边界；离线时仍运行同一个 Loop，记录替身返回已保存的模型回复和工具结果，逐次比较请求、参数、顺序、完整消息、计数及终止原因。独立门禁不重跑候选代码，而是校验证据、读取原宿主策略，再调用原 `quality.Decide` 重算判定。保存的 verdict 仅用于对照。

这验证的是外部结果固定时的控制流、用量一致性和判定聚合。工具副作用、构建测试、行为探针以及供应商响应的真实性不由回放再次证明；这些是原执行证据的边界。回放不访问模型服务，不执行仓库命令，也不恢复或修改工作区。

## 新记录协议

每个新 Runner Run 独占创建根目录的 `trace.jsonl`。`internal/trace` 不依赖 Agent 或迁移场景，使用版本 1、JSONL、开始/结束两条记录。每条包含 Run、span、parent、step 身份、序号、时间、状态、错误类别、载荷和前条/本条摘要。格式参考 span 的组织方式，不依赖 collector。

核心 span 是 run、step、llm_call、tool_call、budget_reserve、budget_settle、gate_check；另有准备、基线、阶段和 Agent 取消检查边界。一个 step 是一次模型请求和它返回的整批工具调用/结果；最终回复也是一步。取消边界保存当次检查实际观察到的状态，不能事后用终态猜测取消位置。

模型载荷保存准确的消息、工具定义、模型名、完整回复（finish、usage）及错误身份；工具载荷保存完整参数、原始结果与独立执行错误。摘要不能代替回放载荷。文件仅宿主可写，模型凭证不进入配置或 trace；消息和工具输出仍是受控运行材料，不能默认公开分享。

文件权限 0600，每条完整换行记录写入后 `Sync`，创建时同步父目录。序号、摘要链及 span 配对用于发现损坏；不提供对恶意重写整份记录的签名认证。仅忽略没有换行的最后残片；完整坏行、中间损坏或非法配对报错。开放 span 可以用于诊断，但不算完整回放。

首版每行最多 16 MiB，回放材料有读入上限。超过限制时停止记录和执行并保留诊断，不截断载荷后假称可回放。新格式尚无压缩、轮转或跨版本迁移。

## 预算与失败

预算埋点在 `budget.Model.Complete`，使用账本的真实 call ID。预留先持久化，再确认 trace，最后才允许模型 dispatch。预留已提交但记录失败时，保留占用，禁止 dispatch。供应商返回后即使 trace 出错，也必须先结算实际 usage；记录错误不能回滚费用或触发重复结算。

回放逐请求核对消息/工具摘要与 usage，校验完整账本及每 Run 的 call 集合；新 trace 额外核对 reserve/settle 的 ID 和状态。已知、预留、未知占用分列；父 span 和两阶段事件不重复累计用量。模型调用次数指 Loop 本地尝试，账本准入与未准入次数另列。未获得冻结价格依据时金额为 null，不把 token 额度当货币账单。

`failures` 按每 Run 一个主因汇总，保留具体失败检查作为次因。区分编译、测试、预算、门禁拒绝/证明不足、工具、模型、超时/取消、设施及未完成。分母同时显示全部 Run 和终态未成功数；未完成单列，零分母 N/A。这里的成功是原流程正常放行，不是 P1 的独立真值正确性结论。已修复的中间工具错误不把最终成功 Run 算成失败。

## 历史记录兼容

五个历史 Run 已有完整对话、工具结果、输入和门禁证据，但没有原始 Reply.Finish 或工具 span 时间。只对完整 `Completed` 对话启用 legacy 回放：成功 Loop 不变量确定中间回复 `tool_calls`、最终回复 `stop`；输出明确标为推导字段，不生成伪历史 span 或时间。

工具定义从保存的 root 清单与现有 wire 定义还原，必须通过账本逐请求摘要验证，不能凭相似提示认定相同。失败、截断或在途历史缺少的响应/错误不猜测，明确拒绝完整回放。历史调用与工具计数、usage、配对任一不符都会失败。

## 验证重点

- 用生产 Loop 录制和回放正常、多工具、未知工具、模型截断/协议错、工具错、预算拒绝、末轮违规、取消及超时。
- 篡改请求、工具 ID/参数/结果、用量、结束原因、输入、策略、证据、账本或 trace 时拒绝通过。
- 在真实辅助进程 SIGKILL 后读取确认记录；开放 span/残缺尾行不当作成功。
- 验证记录失败前不 dispatch、调用后仍结算；使用真实 Runner 的受控模型与本地门禁补足生产集成。
- 对五个既有真实 Run 执行只读 CLI 回放，原文件前后指纹一致；结果不新增迁移成功样本。
