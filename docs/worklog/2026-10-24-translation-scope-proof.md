## 1. 当前问题及本步目标

最近原候选 `7d7dd9cad65b36c67609295eed106aa6f5e6c64608015efd048928b3951de9cc` 已完成交付，原门禁只有 request_scope 为 unknown。两个配置的类型报告均为 complete / covered / direct_timeout_boundary / 30 秒，原测试及行为通过，固定参考也通过。它有充分证据支持直接 RPC 边界，但结构比较尚未解释全部生产改动。

当前 [structure.go](../../scenarios/rpcx/translation/structure.go)从认证基线构造 API 适配，再对 AST 取指纹；仅消去指定位置的 WithTimeout/defer 和 time 导入。它保留普通注释、新的 rpcTimeout 常量，以及 Call 的 callCtx 实参。候选因此与期望结构不同。这里列的是实际存在的差异；未做单因素消融，不把某个差异单独称作唯一原因。

更关键的是，[analysis.Call](../../scenarios/rpcx/analysis/types.go)只有文件、行号、函数、SDK、covered 和时长等事实，没有精确派生/实参节点及对象用途关系。仅凭 covered 不能安全地删除同一函数里所有 WithTimeout、统一替换同名标识符或消去常量。行为通过也不能证明映射、分支和错误处理完全未改。

本步目标：**把能够解释的迁移改动逐项绑定到原字节和已证明对象，再检查全部剩余生产结构。** 能证明的范围才通过；额外业务改动、指令变化或绑定不足继续留下具体缺口。

收益判据是增加可复用的证明形态且不放过已知错误，不以“让这个历史样本变绿”为目标。原实验仍是 NeedsAttention、自动成功 0/1；交付自述计数错误也不会因新增结构证明而消失。

## 2. 选择依据与接受的代价

优先保证绑定与覆盖真实、业务改动不会被消去、证据可审查，其次减少普通写法造成的人工确认。接受支持范围仍窄及一次分析协议的增量维护成本。

| 方案 | 对本次的作用与代价 | 本次选择 |
| --- | --- | --- |
| 继续全部交人工确认 | 没有新增判定风险或代码成本；这类简单命名/常量差异仍反复需要源码复核 | 保留为越界时的结果，本次选择增加有限支持 |
| 引导 Agent 严格生成固定模板 | 生成改动小；需要约束局部名字、常量和注释，不能解决验证器对异构写法的证明能力 | 不作为验证器方案；以后可独立观察提示收益 |
| 类型覆盖和行为 pass 就跳过 request_scope | 可立即放行此类候选；会丢失对未覆盖字段映射、分支及错误处理变化的检查 | 不采用 |
| 继续在宿主按名字扩 AST 例外 | 只改场景模块；会重复 Go 对象/常量绑定，重名、遮蔽及跨配置使用容易被错误消去 | 不采用作为新路径的绑定依据 |
| **同一次隔离类型分析补充有限绑定证据，宿主做剩余结构比较** | 使用已有 go/types 及完整原快照；无需增加包加载次数或执行候选，但要扩证据契约与消费校验 | 采用，限现有直接边界 |
| 重建 SSA、跨函数等价证明或通用插件体系 | 支持更广；没有证据说明当前需要承担该复杂度 | 暂缓 |

沿用 [ADR-003](../adr/003-typed-migration-analysis.md) 的类型身份与组合判定、[ADR-004](../adr/004-analysis-execution-boundary.md) 的隔离边界。现有 worker 已在原位置证明本次边界，不需要先实现早期设计的“期限派生前准备语句”。只恢复该旧设计中与当前证据直接相关的范围证明部分；共享文件常量、helper、准备前缀和测试失败提示变体继续暂缓。

## 3. 首版支持契约

### 3.1 只归约已证明的直接边界

对象限固定两个 adapter 的 Translate 方法，每个必需配置恰好对应一个真实 v2 SDK 直接 Call，必须已通过现有覆盖与对应检查。父 ctx 是原函数参数、标准库 WithTimeout、30 秒求值、同一派生对象传给 RPC、正确 defer 释放及受限控制流，继续由 worker 基于原程序证明。

在比较副本中只允许：

1. 移除这次已证明的派生语句及对应 defer；原 guard、请求/响应构造及业务处理保留。
2. 将**该 Call 的 ctx 实参节点**对应回基线适配位置的父 ctx，不对整函数做字符串或名字替换。兼容现有同名 ctx 赋值及新 callCtx 对象，两者均记录实际对象关系；不假设所有 := 左值都是新对象。
3. 若声明和全部用途均获证明，消去下节限定的新期限常量，以及归约后确实没有其他用途的新增 time 导入。
4. 核对编译/工具指令后，在指定适配器的比较副本中忽略普通注释。

只有派生对象用于该 RPC 实参、cancel 对象用于对应 defer 等受限用途才能进入新归约。出现额外引用、重绑定、提前取消、闭包捕获、条件路径、用户 helper、其他业务语句或不能确定的绑定，保留 unknown；不得扩大现有 covered 的定义来迁就结构归约。

### 3.2 文件内常量及双配置

每份适配器文件最多消去一个新增、未导出的包级单常量声明；不能覆盖基线已有名，不能是 var、分组/iota、多声明或函数求值。首版只接收数值字面量、受限算术及按类型识别的 time 常量表达式，实际 Go 常量值必须是 30,000,000,000ns；显式 time.Duration 类型可接收。任意 compile-time 表达式不自动纳入支持。

该常量只用于本文件已证明派生的时长实参；worker 检查活动包内真实对象的全部用途，宿主检查全生产快照中的声明/引用与两配置证据是否闭合。相同私有名字可分别出现在互斥 adapter 文件中，不能把两份声明误当成同一对象，也不能忽略未活动文件中的额外用途。无法闭合时不消去；共享 translation_types.go 中的新常量暂不支持。

错误时长继续由类型迁移检查 fail；常量值正确但用于额外业务逻辑时 scope 不通过。其他新声明、导入及生产文件变化均留给完整剩余比较。

### 3.3 普通注释不吞掉指令

只在解析出的注释节点上操作，不用正则删除源码字符串。首版要求 adapter 包前 build-tag 原文与基线一致，并继续执行实际配置选择检查。新增、删除或移动 `//go:`、`// +build`、`//line`、块形式 line、`//export`、生成代码标记或其他不能确认的工具指令，不能按普通说明被忽略；新归约遇到这类额外指令时保留缺口。

普通文案与位置可变化，例如 v1 改 v2 和新增期限说明；原字节、文件摘要与被忽略注释范围仍保存。其他生产文件和受保护路径不因本项获得忽略注释的许可，生成 mock 继续逐字节保护。

## 4. 证据、接口与阶段顺序

建议在现有 Call 上增加可选 `BoundaryEvidence`：使用自己的证据版本，记录完整/不支持状态、原因，以及父参数、派生语句、defer、RPC ctx 实参、可选常量声明/使用的角色化节点。节点含文件、字节起止、原片段摘要；对象对应由 worker 用 types.Info 校验后输出，不能持久化 Go 内存对象地址或让宿主按标识符名补猜。

这是对现有分析报告的可选增量；基础 covered / violation / unknown 语义保持。旧报告没有该证据时可继续用于旧分析，不能用于新归约。新增证据中的不支持原因单独保存，**不混入现有调用覆盖 Gaps**，避免 configuredCoverage 将范围证据不足误算成新增 RPC 覆盖缺口。宿主严格校验已知证据版本、角色/数量、范围与原字节、SDK/调用身份、配置和材料绑定；未知版本或不一致不能被消费为通过。

不增加新的类型加载服务、重复宿主类型检查或默认多跑一轮 Inspect。证据在当前隔离 worker 的同一次加载内产生，候选不执行 init/业务/测试；原输入不改写。若这个增量必须扩大为通用 AST 编辑协议，先停止并收窄。

Translation 当前 scope 在配置分析前计算，新路径应在两个配置的类型结果保存后完成：

```text
认证输入 → 构造基线 API 适配 → 两配置构建/类型分析及现有检查
         → 消费同一候选的绑定证据 → 比较副本的有限归约
         → 全部剩余生产结构比较 → 原 quality 聚合
```

保留旧模板匹配作为兼容路径；新路径必须有同一输入/工具/配置的精确证据，不能只读已聚合的 migration_completeness=pass。配置构建失败、缺分析或越界时 scope 保持 unknown/blocked，并保留已有诊断；任何已知违规仍按原聚合优先 Rejected。

新 `scope-proof.json` 应记录规范/基线/候选、分析工具和每配置报告摘要、原文件/节点摘要、已解释改动、指令核对、期望与剩余结构指纹、匹配结果与未解释位置。剩余比较覆盖所有生产文件、函数签名、请求/响应、错误链、tracing 和声明；不是仅比较 RPC 片段。证据保存/绑定失败是验证错误，不产生可用最终通过结论。独立审计应核对这些引用与归约记录，避免只有结果布尔值而无法追溯。

## 5. 版本、旧结果与交付边界

依据 [ADR-007](../adr/007-host-owned-task-profiles.md)，新判定规则使用新的 Translation 验证器版本及宿主 Profile ID；保留已发布 v1 Profile 的内容与旧规则入口语义，不把同一 ID 原地重新签名。具体入口沿既有宿主选择实现，不引入版本插件框架。新工具材料与证据摘要进入新报告，旧冻结协议/数据/参考补丁/oracle 不改。

现有规范 v0.4.0 的业务约束不变，变化的是自动证明范围。新 worker 证据及旧报告的消费边界、Profile 选择、原版本审计须一起验证；旧二进制和旧实验材料仍按其原源码/协议复验。

原模型候选只在独立新副本进行开发校准，使用明确的新输入描述及验证版本。即使新门禁得到 ReadyForReview，也只是新工具对已见输入的校准；原实验仍 NeedsAttention、原自动成功 0/1，交付自述计数错误和完整复核 fail 继续披露。本步不运行新真实模型、不修改 Agent 提示或增加自述评分规则。

## 6. 验收计划与实施顺序

确认后完成一个可验收能力，设计、实现与验证记录一起提交：

1. 增补 worker 的有限绑定证据与严格宿主校验，先证明它没有扩大原调用覆盖范围。
2. 接入 Translation 归约、完整剩余比较、双配置证据及新版本/Profile/审计，保留旧路径。
3. 校准拆分差异与已知错误，完成三类交付及输入/资源保全，再决定是否值得推广；不先追加生成。

| 验收对象 | 预期行为 |
| --- | --- |
| 差异分解 | 从固定正确构造分别加入普通注释、合法不同派生名、文件内常量及组合；新证明 pass，明确区分各因素与组合，不以真实样本单例通过代替覆盖 |
| 精确绑定 | 同名非标准 WithTimeout、错误父 ctx、遮蔽对象、额外 cancel/派生 ctx/常量用途、重绑定或 helper 不得通过新归约；报告 covered 不等于有合格范围证据 |
| 已知违规 | 5 秒常量、缺 ctx、提前取消、改请求/响应映射、吞错、取消后 Store、删断言和改保护文件：检查必须 fail 或保留缺口，整体不得 ReadyForReview |
| 剩余结构 | 原 RPC 边界正确，但另改分支、错误字符串、返回值、接收者/字段或额外声明：残余差异可定位；mapping-helper 等价但未证明形态仍 NeedsAttention |
| 注释/指令 | 普通注释、格式允许；build 标签和额外工具/line/生成指令变化不被消去；字符串字面量中的注释符号不受处理 |
| 双配置 | 两配置各自节点/对象对应，拒绝借另一配置报告、错误标签、遗漏非活动文件引用；共享常量仍保留未知 |
| 证据故障 | 篡改输入/工具/报告身份、节点范围或原文摘要、角色/用途、缺配置、未知证据版本、保存失败和验证取消均不可形成通过结论 |
| 真实隔离与回归 | 在原字节副本上使用实际 Docker Inspect/Evaluate：正例、错误时长、未证明 helper 及最近原候选；所有必需配置/到期按原契约执行，输入不变且精确容器回收 |
| 完整交付与兼容 | 新版本的 ReadyForReview / Rejected / NeedsAttention 三类 Runner 产物与审计一致；旧 v1 校准及至少一个旧真实批次审计保持原结果；独立参考规则不改 |

拆分样例和新反例作为新的开发材料保存，不原地修改冻结 manifest。对于完整性/节点绑定等纯机制使用构造测试；实际加载、三类完整门禁及交付不能由伪造报告冒充。只运行受影响机制及所需集成回归，不重跑付费实验。

**停止/改选信号：**若要支持当前形态必须复制一套类型绑定、增加无界节点白名单或一般数据流分析，先收窄；若坏补丁被归约后放行，先修证明并停扩范围；若仍需人工确认，明确报告原因，不能隐藏 unknown 完成验收。若材料/版本兼容成本明显超出局部收益，保留人工确认并重新评估，不为单个候选承担通用引擎成本。

## 8. 确认后的实现与验证

用户确认后按上述有限范围实现，未扩展共享常量、helper、派生前准备或跨函数证明。设计和实现作为一个可验收工作提交。

### 8.1 类型事实与范围归约分层

新增 worker/evidence.go，在现有 covered 分支中补充可选 boundary_evidence。原调用状态、时长与覆盖 Gaps 不变；额外 child/cancel 用途、导出/共享常量或不支持的常量表达式只令这份附加证明 unsupported。其 schema 1 独立于分析报告 schema 2，使用物理字节范围和原片段摘要，不保存 Go 对象指针。

[宿主校验](../../scenarios/rpcx/analysis/boundary_evidence.go)核对版本、角色唯一性、节点类型/关系、活动包文件摘要和原文锚点。WorkerMaterials 绑定实际执行的三个源码文件；ScopeMaterials 另加入宿主报告/比较/校验源码。没有重复类型加载；宿主只解析已绑定源码以核对节点并构造比较副本。

[新范围证明](../../scenarios/rpcx/translation/scope_proof.go)收集 default/rpcx_alternate 同次分析，逐份核对输入、工具、标签及原调用配对。归约只操作精确派生/defer、指定 RPC 实参和受限新常量；完整快照中其他同名位置会保守形成缺口。所有生产文件仍进入剩余比较，测试由原测试完整性检查负责，go.mod 由原依赖检查负责。普通注释仅在两个已证明适配器中忽略，记录其实际范围和摘要；build-tag 原文字节及位置保留，额外工具指令形成缺口。

scope-proof.json 保存 schema、输入、worker、各配置报告/比较摘要及逐文件结构指纹，scope.json 保留原质量检查接口。任一合法归约之后仍有残余结构差异则 request_scope 为 unknown；已知违规继续由原组合判定优先 Rejected。缺配置或越界不会回退到“covered 即放行”。兼容路径由 v1 入口保留，v2 不以旧模板绕过精确证据。

### 8.2 版本、交付与审计

### 8.3 调试记录与验证口径

首轮分析回归失败：宿主校验误把其他既有 SDK 夹具的三参数 Call 也限定为四参数。改为通用协议接受已支持的三/四参数，Translation 场景仍限定四参数。失败日志 analysis-first.log / analysis-debug.log 保留；修正后分析回归及竞态对照通过，没有扩大旧 covered 的定义。

注释核对从比较整个 package 前缀收窄为比较 build-tag 原文与物理位置，允许不移动标签的普通 package 文档；随后补上标签尾部空白变化负例，避免 TrimSpace 使“原文一致”变成仅文本近似。被忽略普通注释也补入逐文件证据。最终补充由范围竞态对照覆盖，并以当前审计读取完整 Docker 归档核对。

所有本轮验证均为离线夹具、脚本化模型或本机模拟服务，没有读取 .env、调用能力/生成 API、修改原协议/候选/实验或追加付费尝试。脚本调用和 Token 数仅是受控账本机制数据，不是实际供应商用量。旧参考及校准 freeze 不改；普通项目回归跳过的显式集成项不计为已运行。

验证产物统一在 runs/translation-scope-proof-01/，未入 Git。
