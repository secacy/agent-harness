# P1 基线与消融：执行设计

日期：2026-10-31。目标与验收见[需求](../REQUIREMENTS.md#p1基线与消融)，当前进度只在[开发入口](../README.md)维护。本文取代旧单次配对消融草案作为本轮设计依据；正式实验仍需冻结协议与实际资源授权。

## 研究问题与策略

比较相同模型与资源条件下，最小任务提示、完整迁移生成流程、最终独立门禁三种策略的端到端结果。B/C 生成配置相同，但每个任务、组别和重复均独立生成；不存在共享候选，也不以配对种子或相同模型版本暗示供应商采样可重复。

| 条件 | A 裸 Agent | B 无门禁 | C 完整系统 |
| --- | --- | --- | --- |
| 输入、迁移规范、原始测试、只读基线、SDK、保护路径 | 相同 | 相同 | 相同 |
| 文件工具与普通 `go_check` 构建/测试反馈 | 有 | 有 | 有 |
| 预算通知、`final-response-v1`、硬预算 | 相同 | 相同 | 相同 |
| 迁移专用检查提示 | 无 | 有 | 有 |
| 按需 `migration_check` | 无 | Translation/Workouts 最多 2 次 | 同 B |
| 提交后的独立门禁 | 无 | 无 | 有 |
| 放行条件 | 正常提交并完成交付 | 正常提交并完成交付 | 正常交付且 `ReadyForReview` |

`final-response-v1` 属于本轮控制变量：所有组都能在额度边界交接候选，避免把预算末轮行为混入迁移反馈差异。A 仍获得完整规范、修改边界与提交方式，移除的是额外的 RPC 边界、测试保真和生产变更审查步骤。原始规范本身的约束继续存在。三组都只通过固定的普通 Go 命令运行候选，不新增任意宿主 shell 工具。

当前完整流程是模型通过 `go_check` 自行检查并修复，另有有限的按需测试结构诊断；不存在最终门禁判定后继续修复的生产循环。B/C 使用现有流程，不为 P1 新造这样的循环，也不把组间整体差异单独归因于某个反馈工具。

## 实现选择

采用 Runner 内的显式实验适配 `RunExperiment`，复用输入认证、准备、基线、预算包装、生产 Agent 循环、仓库工具和现有门禁。生产 `Run`、`CampaignExecutor`、历史 `Replay` 的交付契约保持独立；实验使用 `experiment-attempt.json`、`experiment_attempt` trace 根和明确的 `Submitted` / `Released` 字段，不为 A/B 编造质量 verdict。

| 备选 | 取舍 |
| --- | --- |
| 给生产 Run 增加任意跳过门禁选项 | 会使 Completed/审计含义含混，不采用 |
| 新写一套 Agent 和执行设施 | 重复安全、预算与输入边界，容易产生额外组间差异，不采用 |
| 实验适配复用阶段能力，单独收据与聚合 | 采用；代价是实验入口依赖 Runner 内部阶段，范围限定为本轮四仓 |

准备、生成、门禁分别计时并独立派生截止时间，C 的门禁耗时不能挤占生成阶段。收尾在有限独立上下文内固定候选、补丁与已有记录。生成失败时可保存残留候选用于独立评测与诊断，但不能将其视为正常提交或补计成功。发布、输入保护或持久化失败必须撤销放行。

实验协议与聚合放在 `scenarios/rpcx/l2/ablation`：预登记全部 36 个 slot、串行执行、轮换组别顺序、每次使用独立目录/对话/账本账户与候选。整体账本上限等于各次额度总和，单次耗尽不借用其他次额度。不使用旧 round 中每任务一次、仅 ReadyForReview 算放行的聚合口径。

## 真值、冻结与资源

独立真值准备与四仓人工复核材料见[真值记录](2026-10-31-p1-truth-review.md)。复用现有独立行为参考；候选正确性由自动参考与测试保留/变更覆盖复核组成，交付说明准确性单列。原 `evaluation.Assess` 的旧口径不修改。

正式运行前必须固定输入与源码、模型身份和上界来源、实际提示/工具配置、镜像资源、阶段时限、三次重复及运行顺序、参考数据与工具身份、指标、失败处理。四仓逐一人工复核不能由助手代签；运行后候选若缺复核，保留未知，不能以门禁 verdict 或自动 pass 补齐。

模型与费用上限尚未获得本轮授权，不读取凭证执行正式调用。预算估算同时列历史观测和最坏 token 额度；金额使用冻结价格来源，缓存用量缺失时记未知。硬 token 上限可提供按冻结单价计算的保守金额估计，但不宣称能控制供应商事后改价或直接等于供应商账单。当前 Docker CLI 可用、守护进程未运行；此状态影响实际容器校准，不阻挡本地机制测试。

## 分母与验证

每组固定 12 次、每任务每组固定 3 次。失败、未启动、未提交及未知均进入结果表；缺少收据不按成功或零成本处理。自动成功、错误放行、误拒按需求定义计算，零分母为 N/A；未知放行同时给出可确认范围，范围不是置信区间。每项资源分布列观测数、缺失数、均值和范围，不能静默忽略缺失。

验证先覆盖：策略实际生效且 B/C 生成配置相同；无诊断反馈泄漏；门禁禁用时不执行提交后检查；C 拒绝和证明不足不放行；输入改变、取消、预算耗尽和收尾失败；候选固定与 trace/账本回放；零分母、未知、重复或共享 Run、丢失预定 slot、候选与说明结论分离。之后用正确、错误及证据不足的受控候选进行容器校准，校准输出显式标记，不加入正式 36 次分母。

正式实验不根据结果追加尝试或修改提示/参考。局部模型或候选失败保留记录并继续其他预定项；共享输入、预算或资源完整性失败停止后续调度，未启动项保留。协议变更另起版本，旧结果不覆盖。

## 已实现工作单元与证据边界

首个工作单元实现实验策略适配、可认证回放、36 项调度及共享硬预算、所有固定候选的独立参考入口、真值/说明分列、指标聚合和 JSON/CSV/Markdown 输出。`DescribeExperiment` 与实际 Agent trace 逐字核对，支持在运行前导出确切的模型可见定义。Docker 命令复用既有资源归属注册和未知回收后的停止机制；这不等于 P4 越权实测。

机制测试覆盖普通 A/B 不执行提交后门禁、C 调用已有门禁、B/C 同配置独立生成、输入漂移、阶段和整体超时、失败残留、收据/候选/参考损坏、36 个工厂失败保留分母、模型身份漂移停止、索引停在 starting 的完整终态只读认证、初始 Running/截断收据保持未知、参考局部失败继续及资源异常停止。独立参考测试对真实来源身份和材料结构进行校验，候选命令通过执行替身返回；不能将这些测试称为真实候选容器验收。

原始验证日志放在忽略目录 `runs/p1-mechanisms-race-2026-10-31.log`、`runs/p1-runner-race-2026-10-31.log`。实际命令准备产物位于 `runs/p1-prepare-2026-10-31/`，包含 36 项草案、12 份任务/组定义和四份待填复核模板；不是正式冻结材料。当前还需完成源码/模型/环境冻结、预算授权及容器校准，之后才能执行正式 36 次实验并按 P1 验收。
