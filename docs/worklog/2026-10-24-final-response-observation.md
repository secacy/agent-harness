- 日期：2026-10-24（Asia/Taipei）。
- 状态：设计已确认，新协议准备及离线验收完成；待本版真实外发/消费授权，尚未启动。
- 受测代码起点：`d4e5b2b`；[末轮交接实现与验收](2026-10-24-final-response-handoff.md#9-确认后的实现与验证)。

## 1. 当前进度与本次问题

末轮仅回复已经通过受控模型、本机 HTTP、预算与审计对照；固定候选经实际工具和独立门禁保留三类判定，非法末轮调用没有执行。尚未观察真实模型在该策略下怎样结束任务，也未证明有效交付改善。

上轮 Translation 用满 40 次模型调用，最后一次仍编辑，因而没有提交或进入运行时门禁。本轮回答三个问题：

1. 真实请求到达仅回复边界时，服务是否接受保留历史但没有工具声明的请求，模型能否给出有效最终回复？
2. 当前候选是否实际进入并完成独立门禁，交接时有没有未复验的编辑或未解决问题？
3. 原运行判定、固定参考与源码复核是否支持有效自动成功？若只有提交改善、候选仍错误，分别报告。

若提前提交，记录提前交付及质量结果，**末轮兼容性记未观察**；不得延迟提交、故意浪费额度或再跑一次来制造末轮。若在末轮前因费用、时间、工具或模型错误停止，也不能据此断言末轮机制失效。

## 2. 方案选择与代价

优先级是观察真实交接路径、限制费用与改动范围、保持质量标准；本轮不以估计提升幅度为目标。

| 方案 | 能回答的问题与代价 | 选择 |
| --- | --- | --- |
| **一个 Translation，全新迁移，启用末轮策略** | 复用已有完整输入和参考，成本有界；可能提前结束而无法观察末轮，单次不支持因果结论 | 采用，接受没有触发边界的结果 |
| 同源码下策略开/关各一次 | 比单个历史对照更接近策略比较，但费用上限翻倍；每组一次仍不足以区分随机波动 | 暂缓，只有需要研究可重复效果时再定重复次数与分母 |
| 直接续接上轮第 39 次历史 | 容易触发指定末轮，但继承已知错误候选，改变输入/恢复语义；不能代表全新自主迁移 | 不采用；机制重放已有证据 |
| 将额度压到两三次以强制触发 | 能测服务协议兼容，却剥夺迁移机会，无法回答完整交付问题 | 不作为本轮迁移观察 |
| 再跑四个仓库或同时提前冻结编辑 | 覆盖更广，但成本和变量增加，难判断是哪项变化起作用 | 暂缓 |

保留上轮的 baseline 可读、DiagnosticLimit=2、40 次模型/80 次工具和 10 分钟 Run。唯一计划中的生成策略变化是 `completion_policy=final-response-v1`，包括其从第一轮起提供的预算说明，以及边界处关闭工具；不能把它称为只改变了最后一个 HTTP 请求。

不追加“不要新增探针”“必须诊断”等针对旧轨迹的提示，不提供旧候选、错误行号或参考补丁。仍从认证 v1 基线开始，允许自主提前提交、报告未解决项或失败。新旧运行来自不同时间、模型可能波动，旧结果只作背景，不能作为随机对照或合并分母。

本轮不修改业务门禁、参考答案、超时、模型容量或工具额度。Token 是计量上限而非金额保证；最后一轮依旧需要按 Q 获得准入，空工具不会缩小预留。未知用量保守占用，可能提前阻止请求。

采用新输出/启动收据/结果目录，准备阶段固定实际路径与完整摘要。一次执行启动失败、能力不符或预算拒绝也保留记录，不自动复用许可再启动。这里只记录历史能力和拟用配置，没有发起查询或声称当前供应商仍提供相同能力。

## 4. 分析契约：不能继续假定工具集合恒定

旧 [analyze.py](../experiments/translation-diagnostics-dev-v0.1.0/analyze.py)按完整 tools.json 重建每个有助手回复的请求，不能原样用于本次。确认后只在新协议中适配离线分析器，保留旧文件字节；不新建产品级调用日志。

分析同时消费 Plan、Run Input、agent.json、账本和固定 tools.json，核对策略一致、预算通知、模型/工具计数及 FinalResponseAttempt。按执行历史确定边界并核对标记，不能单凭标记任意将一次请求换成空工具：

- 正常请求使用冻结的完整工具集合；仅回复请求使用 Go JSON 的 `Tools: null`，与空数组区分。重建的是 Complete 接口输入摘要，不是 HTTP 字节证明。
- 已准入请求、账本拒绝、本地尝试但未准入、已有助手回复分别记录。取消或设施错误可能没有准入/拒绝；保留未知，不虚构 call_id 或服务已收到请求。
- 模型提出的 tool_calls 与有 ToolResult 的执行尝试分开。仅回复轮若有违规请求但没有执行结果，计拒绝而不重放编辑；若出现执行结果，按一致性违规停止行为推导。
- 保留现有成功 replace_text 重放、诊断点快照、最终候选及来源稳定性核对；不运行对话中的命令、不把模型自述当成执行证据。
- 提前提交、末轮有效提交、末轮错误/截断、末轮未准入、边界前失败单列。有效提交后验证超时与没有提交也分开。

观察表至少保存：边界是否到达及原因、是否准入、是否收到回复、退出原因、最后成功编辑的调用序号/候选摘要、之后本地 build/test 的配置与结果、诊断对应候选与最终候选是否相同、原门禁是否完成、最终三类判定及独立参考/复核。最后修改在旧检查之后时标“未针对最终候选复验”，不把旧绿色结果移给新候选。

提示从首轮就变化，因此模型可能更早收尾；若没有触发末轮，只报告本次提前提交事实，不断言提示造成改善。原记录未保存逐请求 finish_reason 原文时，不编造该字段；使用适配器/Loop 的实际退出和已保存回复，明确可核对范围。

## 5. 结果口径与停止/调整信号

固定计划 N=1；实际 Run R、有效提交、原独立门禁完成、放行 A、NeedsAttention、Rejected 和有效自动成功 S 分列。生成前拒绝不能从计划分母删除。S 仍要求原 Run Completed/ReadyForReview 且完整参考及实际复核 pass；A=0 时错误放行率无定义，未知不补为正确。

| 观察结果 | 结论与后续选择 |
| --- | --- |
| 到达末轮、有效提交、门禁完成 | 真实交接路径有一次证据；再按候选质量解释收益，不能直接称迁移成功 |
| 提前提交 | 有新策略下的交付观察；末轮行为未观察，不强制追加一次 |
| 提交了错误或证据不足的候选 | 如实保留 Rejected/NeedsAttention；仅解决交接不足，回到具体生成错误或证明缺口，不能放松门禁 |
| 末轮仍提出工具或请求被服务拒绝 | 保留失败与计费；先核对适配契约，不追加纠正请求或取消工具禁用 |
| Token/时间先耗尽，或验证未完成 | 定位资源及阶段，不据此提高本版预算；后续另行权衡资源分配/验证时间 |
| 输入/环境/材料漂移 | 停止启动，保留零生成或实际准入事实；修正需要新版本或明确的新启动安排 |
| 轨迹或来源无法核对 | 相应行为结论标不可核对，不能由模型总结补齐或重跑选择更好结果 |

费用列已知输入/输出、未知/在途占用、准入/拒绝、工具及诊断次数、Run/宿主墙钟、已记录命令耗时。独立参考/复核另列；实际金额、人类活动时间及无法拆分的增量成本标未知。单次 0/1 或 1/1 只是原始观察，不报告提升百分比或泛化结论。

有可认证部分候选的失败也做事后参考/复核，但不能晋升原 Run；没有原 verdict 时不将部分参考挂成原自动成功，沿既有独立 Assess 路径保存。原始判定、候选和历史数据均不回写。

本版一次结果完成即停止，不以“尚未触发边界”或“结果不理想”为由连跑。原 M3—M5 留出、人员口径和总体验收缺口不因本次结果改变。

## 6. 确认后的两步工作

1. **准备与离线核对。** 固定新 batch/enrollment、源码/二进制、环境与参考材料；把新策略纳入设置摘要，适配并校准分析器。用已保存的受控混合批次校准合法交接/非法末轮，并用明确标记的合成记录覆盖提前 stop、工具耗尽、未准入、缺回复、null/空数组错配及标记/账本篡改。校准缺依赖应失败，不以跳过宣称通过。两级配置检查须零 API/零生成，启动收据独占和停止流程沿用已有约定。
2. **展示固定范围，再取得本版授权。** 准备验收后将设计、协议及脚本一起提交；展示源码/协议身份及费用/外发边界。只有明确授权才读取 .env 的 API Key，发起一次 Models GET 和本版唯一生成。之后完成实际源码复核、固定参考、原运行汇总、轨迹分析、审计、补丁重放、导航、来源保全与精确资源回收。

设计阶段仅修改文档，未准备协议或执行任何实验；当时等待确认，未单独提交。用户确认后的准备与验收见第 7 节。

本轮核对：三份变更文档的 197 个本地链接目标、31 个锚点及代码围栏有效；git diff --check 通过。未运行 Go 测试或新实验，当时以上校准与效果检查均是待执行计划。

## 7. 确认后的材料准备与离线验收
