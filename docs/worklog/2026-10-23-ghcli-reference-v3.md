# GHCLI 独立参考 v3：响应、错误与 Body 契约

- 日期：2026-10-23。
- 状态：已发布活动数据 v3，并完成声明范围的真实 Docker 开发校准及接口回归。
- 代码基线：6f5da4a。

## 目标与选择

v0.2.0 真实候选在 CheckRedirect 拒绝重定向时将原有非空响应清空。原运行时门禁保留 NeedsAttention，独立参考 v2 自动通过，助手复核确认返回值违反公开规范。上一步已保存可复现的开发正反例；本步将契约加入正式版本化参考的执行链路，不新增模型实验。

| 方案 | 得失 | 选择依据 |
| --- | --- | --- |
| 原地补 v2 探针 | 接入最少，但同一数据版本产生不同字节，无法解释原报告的 pass | 不采用，遵守 ADR-005 |
| 新增一条临时外部检查，保留 v2 为活动参考 | 能捕获反例，但报告、材料绑定和结果汇总未必强制消费该检查 | 不采用，已有独立开发回归已承担诊断职责 |
| 发布 v3 数据，沿用 EvaluateGHCLI 生产副本和证据链，增加必需测试事件 | 新版本可审查、可归因；需要重新验收装配与消费者，旧工具需从原快照复现 | 本步采用，直接补足已有参考的行为覆盖 |

活动 API 继续只执行当前参考，不增加多版本执行框架。v1/v2 数据、历史报告、冻结源码/二进制及原指标保留；当前 API 不声称重演旧版本。新生成若要使用 v3，必须另冻结协议和实现身份；本步只做已见开发校准，不发起生成。

## 契约及执行边界

依据仍为 v0.6.0 第三段对返回值、错误和 Body 所有权的要求，规范、基线、SDK、依赖和运行时门禁不变。新增参考只观察 invokeHTTP 的边界：

- 成功响应保留状态、头和可读 Body，调用方 Close 的错误及释放责任保留。
- 普通传输错误保留错误链，不凭空生成响应。
- CheckRedirect 返回普通错误时保留响应及错误，Body 维持 HTTP 客户端已经关闭的责任。
- ErrUseLastResponse 保留可读响应，不作为错误；Body 仍由调用方关闭。

探针使用内存 RoundTripper，不进行真实网络调用，不读取 case 标签、候选摘要、预期结果、门禁结论或模型解释。可复用上一单元独立编写的契约代码，但不依赖开发回归包或其 manifest；预期标签只在外部校准测试中。该反例已见，不称未见泛化证据。

新文件独立装入删除候选测试的 production 副本，与既有快检同次执行，并加入必需事件集合。断言失败沿用 BEHAVIOR-001；缺事件、跳过、编译/执行设施错误和看门狗超时不能冒充通过。保留所有旧探针及两个实际 30 秒到期检查；新增快检失败时沿用现有流程不再运行到期检查，未执行项保留 inconclusive。

## 验收计划

1. 冻结新目录的精确清单及规范摘要；测试旧两版字节、当前身份、未知/旧版本拒绝、必需探针实际装配与必需事件。
2. 在真实禁网 Docker 中，原样已见候选应为 fail，保留响应的最小修改对照应完整 pass（含两次实际到期）；吞错负例应 fail。记录执行命令、原始事件、条款、前后输入摘要和容器回收，不以模拟事件代替实际行为。
3. 运行参考/汇总及相关调用方回归，检查当前消费者不接纳旧版本冒充新参考；核对既有运行及冻结材料未变。更新命令、进度和支持边界后作为一个工作单元提交。

若 Docker 环境不满足，保留未完成状态并完成不依赖环境的检查，不将本机或模拟结果写成 Docker 验收。无需新 ADR，沿用[版本化数据决策](../adr/005-versioned-evaluation-data.md)。

## 结论与剩余边界

v3 补上了已经确认的响应＋错误盲区，保留旧探针，并通过完整执行链路和正负对照证明新增检查被实际消费。它依然是有限边界的独立参考，不证明所有响应形态、任意业务修改或仓库全行为等价；同一作者与共享基础设施仍可能产生共同盲区。校准沿用已见输入，不计入未见泛化或新模型效果分母。

原 v2 参考 pass、原门禁 NeedsAttention、原助手复核 fail、原候选和所有历史指标保持；保留响应的对照不作为修补后的原实验成果。本步没有读取 .env、查询模型、发起生成或新增评测轮次，也没有重跑 Runner/Campaign 的完整交付流程。

若下一步希望运行时直接识别此违规，先设计生产证据的适用范围、失败/未知分类和材料绑定，再验证完整 Harness 接入；不因新版参考已能抓住一个反例，就扩大运行时自动放行范围。
