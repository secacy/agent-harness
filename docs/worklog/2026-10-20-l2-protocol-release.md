## 实现前的方案权衡

本轮优先回答三个已见开发任务在同样单任务限制下能否完成，保留全部失败与未知；其次减少总批准额度。参数不是吞吐或模型效果最优值。

| 预算方案 | 当前三任务的具体影响 | 选择 |
| --- | --- | --- |
| 全批 600 万，每任务 250 万 | 总上限较低，但三个任务可用额度合计 750 万；某任务可能因其他任务先用掉共享额度而停止，不能把结果仅归因于自己的迁移难度 | 本轮不采用；适合另行做共享紧预算实验 |
| 全批 600 万，每任务 200 万 | 不再竞争共享额度，但单次 Q=1,052,672 后，已知/未知占用超过 947,328 就无法再发请求，比现有单任务限制更紧 | 暂不采用；当前首轮没有证据支持收紧任务额度 |
| 全批 750 万，每任务 250 万 | 总批准上限增加 150 万；在服务与账本契约成立时，共享 Token 池不会额外压缩任一任务自己的上限 | 采用为待授权协议；全批调用 120=3×40，不追加额度或尝试 |

理由：对每个 Target 都有已知＋在途＋未知占用不超过 250 万，三者相加不超过 750 万。因此某任务满足自身预留条件时，不会仅因其他任务合法占用而被全批额度拒绝。执行槽、父取消、基础设施与模型随机性仍可能影响结果，不宣称并发结果等同独立随机生成。未知用量仍保留整笔 Q；250 万不是保证可调用 40 次的额度。

现有入口重新 Discover 后仅检查“预算能预留一次”，不足以约束已发布协议的容量。三个可行方案：只写运行前人工检查，存在 GET 后直接生成的窗口；锁定整个 Models 原文摘要，会被其他模型及无关元数据变化阻断；检查所选模型预算相关字段，范围最小。选择最后一种：可选 expected_context_tokens 必须与当前所选模型声明相等；输出上限仍由已固定 O 与服务允许值核对。该值只用于比较，不能覆盖 Discover 或替代真实预算上界。模型别名背后的实现仍不能由此固定。

容量不符时保存本次能力原文、规范化配置及能力记录，返回配置错误，不创建执行后端、Campaign、Run 或账本，也不发送 POST。探测模式仍可保存变化后的能力用于诊断；省略比较字段保留普通批次行为。不增加恢复、自动二次探测或重试。

本次是具体实验选择，不新增 ADR。协议包放在 docs/experiments/l2-dev-eval-v0.1.0/：协议、真实 batch 配置、静态 Enrollment、能力依据及摘要清单；发布后不原地调参，变化另起版本。实际 Plan/查询时间/Run/候选摘要运行时形成，继续由已实现的发布屏障绑定，不预造未来身份。

## 实施与验收计划

1. 补可选容量比较，验证匹配可生成、变化零 POST 且保留原文、负数在 API 前拒绝、旧配置兼容。
2. 固定三仓、模型、两级额度、Docker、独立参考和复核规则；保存源码与可执行文件的实际身份及能力依据，不读取凭证。
3. 实际执行离线 --check，校验清单、数据/参考身份、镜像与材料摘要，再提交一个完整工作单元。向用户展示具体传输范围、次数/Token/时间上限后才申请本次真实生成授权。

本轮不运行模型或新候选参考，不将协议发布称为 M3 完成。测试和材料检查结果完成后在下方补录。

## 实际实现与验证

入口新增可选 model.expected_context_tokens：负数在本地配置检查拒绝；正数只比较 Discover 的当前声明，不改变真实 Profile。实际生成发现容量漂移时，保存本次原文、配置与能力记录后返回 2，零 POST、无执行器/Campaign/Run/账本。--check 保持离线，--probe-model 仍可诊断变化，省略字段的原命令继续工作。

发布[协议包 v0.1.0](../experiments/l2-dev-eval-v0.1.0/README.md)，含完整规则、实际 batch 配置、Enrollment、此前获授权的能力原文/解析、implementation 身份与 freeze 摘要清单。750 万是提交审查的本轮上限，不代表已取得生成授权或供应商账单上限。协议固定人工复核规则；未安排实际人类复核时自动通过仍未知，不伪造复核者。原示例保留其 600 万草案，文档明确与本轮真实配置的区别。

构建使用 -trimpath -buildvcs=false，避免把尚未形成的发布提交写成未来身份；实施材料固定父版本 1441bc5、545 个实际源码/场景文件的集合摘要及已构建二进制。发布 Git revision 在未来启动记录另存，不预造提交或 Plan/候选身份。实际查询后仍绑定新 Profile/Plan，不硬锁整个模型列表原文。

准备时的两项问题保留：首次协议配置直接以含点号的版本号作为 Campaign ID，被既有受限字符规则拒绝；改运行 ID 为 l2-dev-eval-v0_1_0，协议目录与版本仍保留 v0.1.0。失败配置和检查分别保存在 runs/l2-protocol-invalid-id.json、l2-protocol-check-first.log；最终检查使用修正后的配置。首次只读 Docker image inspect 因沙箱不允许访问本机 socket 失败，经只读权限提升后核对成功；没有拉取镜像或运行容器，也不是一次 Docker 业务验收。
