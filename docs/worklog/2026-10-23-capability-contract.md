# 能力契约与查询原文分离

- 日期：2026-10-23。
- 状态：已验收，限 localhost 模拟服务及离线兼容性；未调用真实模型。
- 代码基线：2b140d4。
- 目标：允许新评测协议接受不影响所用能力的响应变化，保留实际原文身份；旧协议和失败实验不改。
- 触发证据：[GHCLI 唯一启动](../experiments/2026-10-23-ghcli-dev-real-model-01.md)在生成前停止。

## 问题与选择

Models 新增 Anthropic Messages 的 tool_update 元数据，Chat Completions 所用模型及 Token 参数未变，却因整份响应摘要参与计划设置而被拒绝。预算 Profile 的来源身份仍有必要：实际计划、账本和调用必须绑定本次查询，不能直接把历史响应当作当前依据。需要分开运行兼容性与记录完整性。

| 方案 | 对本次附加字段的行为 | 代价与结论 |
| --- | --- | --- |
| 继续精确匹配整份响应，换历史摘要后重发协议 | 再次附加字段仍会拒绝 | 保留最严格的字节约束；不能解决与当前 API 无关的变动频繁阻断运行，只保留为旧协议语义 |
| 所有协议的设置摘要直接排除来源 | 新旧协议均接受 | 实现少，但会改变历史评测的准入与复验语义，不采用 |
| 新协议显式启用 model-contract-v1，设置摘要排除原文身份；实际计划和原文另行绑定 | 所用字段相同时接受，实际原文仍是新的身份 | 需维护两种明确的绑定语义和新策略的原文核对；选择本方案，优先保护预算条件和历史可复验性 |

首版保留 schema 2 的布局，在 Protocol 增加可选 capability_binding。缺省保持原设置摘要算法；仅 model-contract-v1 启用新算法，未知值在本地配置检查拒绝。旧工具严格解码未知字段，因此新协议需新工具，不伪装旧工具可读。无需为相同产物布局另建执行入口或全套 schema。

新算法只额外排除 Profile.SourceSHA256，原有运行 ID/查询时间排除规则保持；provider、endpoint、model、context 和请求输出限制以及预算、时间、输入、并发、资源等全部继续精确匹配。不是“变大就接受”：context 增大同样改变保守预留，必须拒绝。Discover 仍要求唯一所选模型、正数上限及文本输入/输出；服务输出上限只须支持已固定请求限制，并不把未使用的输出容量固定为运行设置。

实际 plan.json 不删除或改写 source_sha256、verified_at。Manifest 继续绑定实际计划全部字节，账本继续绑定实际 Profile。新策略的离线汇总额外读取 models.json 并核对其摘要等于实际 Profile.SourceSHA256，读取 capabilities.json 并核对 Profile 等于实际计划；原文缺失/篡改或 Profile 冲突不发布有效指标。原文是本轮证据，不能为使比较通过而归一化后覆盖原文件。

能力兼容仅覆盖适配器当前使用的文本模式与预算字段；相同模型别名或响应不能证明服务权重、行为和计费实现不变。新增会影响请求/计量的选项时，必须重评契约版本。此次不增加真实请求、修改失败轮次、准备另一版付费实验或自动重试。

## 实现与验收计划

1. 新增显式绑定策略和设置摘要方法，保留旧函数与缺省序列化；验证旧协议仍拒绝响应漂移。
2. 用模拟 HTTP 在新策略下走一次真实 CLI、预算及 Runner 交付；验证附加字段/排版变化可进入受预算生成，关键能力缺失或变化零生成，当前原文进入计划和账本。
3. 用离线汇总验证原文/元数据缺失及篡改不可接受；复用旧轮次复验，核对冻结材料未变。记录证据后提交完整工作单元。

预期对照包含端点/模型/供应商/上下文/请求输出、预算/工具/超时/槽位/输入/引擎变化、未知策略、旧字段缺省、原文丢失/改动与元数据 Profile 冲突。localhost 模拟服务只使用假 Key，不读取 .env，不联系真实供应商；测试结果不计迁移效果。

## 实际实现与验证

改动集中在 round.Protocol：增加带 omitempty 的 capability_binding 与 SettingsSHA256 方法，原独立 PlanSettingsSHA256 函数不改算法。clone、Enrollment 和 Manifest 直接沿用协议值；原 batch 流程在取得当前能力后已有准备屏障，无需新增模型入口或修改预算逻辑。Discover 原有对未知元数据的容忍、文本能力及数值检查足以支持该边界，本轮没有修改适配器生产实现。

离线工具版本升为 rpcx-l2-round-v3，新策略才读取并核对能力原文和 Profile；旧协议保留原材料要求。读取使用现有 reader，来源文件和副本均参与最后的稳定性复核。该核对认证宿主材料之间的归属，不独立解释供应商所有能力，也不防御可信宿主重写整套材料。

首轮聚焦测试中，合法汇总的材料断言失败：测试用 /var 临时路径查 Sources，实际键已经规范化为 /private/var。修正断言使用与读取器相同的 Canonical 规则，未放松来源摘要或修改生产路径；首轮失败保存在 round-first.jsonl。
