# 新 Agent 隔离准备样本试点

- 日期：2026-10-21。
- 状态：新准备 Agent 已交付实际基线及禁网构建/测试回报；主流程仅核对公开元数据，L2 准入未评估。
- 实现基线：c7701ecd80544ebec62d46d5aeb2dee3132b90a7；启动时工作区干净。
- 触发：用户提出使用全新的 Agent 承担准备工作。
- 范围：一个新的半真实候选样本的选源、来源映射与迁移前基线准备；本轮不接入宿主 Profile、不做付费生成或正式效果评测。

## 目标与方案取舍

之前把“独立准备”一概限定成另一位真人，忽略了个人项目可以先采用过程隔离。这里区分两件事：另一个 Agent 可以承担实际准备劳动，并使本轮调优上下文不接触材料；但不能因此称为另一位真人、第三方盲审或统计上完全独立的数据来源。

| 方式 | 本项目下的实际差异 | 选择 |
| --- | --- | --- |
| 当前调优 Agent 直接准备 | 工作容易衔接，但会读取源码/答案，成为已见样本 | 不用于本次隔离准备 |
| 继承全部历史的子 Agent | 可并行执行，但继承既有实验和调优内容，无法达到本轮希望的上下文隔离 | 不采用 |
| 全新对话 Agent，只接收通用契约与排除清单 | 可实际选源和准备，主流程仅收元数据；同模型家族、共享工具权限和文件系统仍构成限制 | 本轮试点采用 |
| 独立人员/环境准备 | 可提供更强的组织和访问边界，但需要真实安排 | 保留原口径，不把试点冒充其验收 |

本轮的“未见”只指当前开发调优对话未读取新样本源码、答案或结果调优，不证明基础模型训练数据中未出现该来源。

## 任务与访问边界

准备者为 `/root/fresh_sample_preparer`，通过 `fork_turns=none` 启动，未向其传递主对话。给出的任务材料仅包含：冻结实现身份、七个已查阅来源版本及同源排除清单、两个共用 rpcx SDK 目录、通用迁移条件和本轮输出/执行限制。未向其提供已有业务切片、模型轨迹、正确补丁、oracle 或历史成绩。

任务启动材料为 `runs/m5-agent-preparation-01/public/assignment.json`，另保存其真实 SHA-256。完整来源、准备代码、映射和基线日志只由准备者在同级 private 目录查看；主调优流程只读取 public 下的来源身份、许可、摘要、环境要求及准备状态，不读取源码、测试名、答案或详细失败日志。普通 Git/交付扫描不纳入这个忽略目录。

这是独立对话及文件访问约定，不是两个 OS 用户、容器或独立权限系统；不得把目录叫 private 就声称主 Agent 技术上无法访问。准备者的访问遵循任务约束，不以过程声明代替安全沙箱或实际人员签署。

准备者最多摸底三个新来源，先固定 U→B、许可与原测试映射，再验证基线；约 15 分钟主动准备作为首阶段范围，遇阻记录真实状态。禁读 .env，禁模型 API、Git 写入和全局配置修改；不修改根 Harness。只运行自己检查的有限切片，容器执行需要禁网、明确资源限额、自有唯一归属并清理自建资源。

## 首阶段交付与后续边界

public/preparation.json 只记录准备状态和允许元数据：实际来源/版本/同源组/许可，真实基线/来源映射摘要、实际配置/构建/测试计数/后端和离线状态、准备者身份、限制，以及 runtime_profile_registered=false、formal_evaluation_started=false。没有实际材料的摘要保持 null；不能把选源或编译成功冒充完整基线验收。

新的 Agent 准备基线不等于这个任务已经成为可执行留出：独立参考、手写对照、可信 Profile 与 v2 分区接入仍需要后续有实际材料的设计和验证。原 `l2-heldout-01` 选择名额及旧实验不回写；该试点单列 fresh_agent_preparation。若以后使用其结果，先在新协议中说明准备者身份和隔离强度，不将本轮准备计为模型迁移成功或原独立人员留出通过。

## 验证计划

- 核对启动材料、冻结 Git 身份、父历史未继承的实际调用及公开状态；主流程不打开 private。
- 准备者回报自己实际执行的基线命令类别/配置数/测试计数及限制；主流程将其标为准备者回报，不冒称主流程独立重验。
- 核对根源码与旧选择清单不变；仅变更活动方法说明，校验文档并提交。本轮不放开任何运行时 heldout 校验。

## 实际结果与验证归属

准备者发布 `public/preparation.json`，状态为 prepared_baseline；公开回执已另存 [agent-preparation-v0.1.0.json](../../scenarios/rpcx/l2/agent-preparation-v0.1.0.json)，不覆盖历史 selection-v0.1.0。所选来源为 icholy/digest，固定 commit 为 104e41263110fbc4690a1c0d6b309cac6e597e56，MIT；另有一个摸底来源，均未进入原排除清单或同源组。

准备者实际执行并回报：固定镜像、自有禁网/只读根文件系统容器，2 CPU、2 GiB、128 PID；一个配置构建通过，13 个顶层测试、含子测试的 54 项通过，失败为 0。原 6 份测试文件保留且字节不变，没有新增测试；原 14 个顶层测试中一个外部服务套件（3 个固定子例）保留但未执行，不能把它算为通过。依赖在准备时公开下载并 vendor，实际基线验证禁网；自建容器均已回收，测试后基线摘要不变。

该结果归属于准备者的实际执行和自检，主调优 Agent 只核对回执结构、任务/来源/计数一致性、公开材料摘要与原代码未变，未打开 private、未独立重跑，不能声称双重验收。准备者确认先固定 B，尚未制作迁移、oracle 或候选补丁。准备 Agent 的平台调用成本未取得计量，不填为零，也不加进原 81 次/1,060,890 Token 的 Campaign 数据。

实际样本是库级协议逻辑切片，应用业务代表性和原 L2 业务样本准入未评估；回执明确 l2_admission=not_assessed。它证明新 Agent 能承担隔离准备和实际基线验证，不证明原独立人员留出通过，不能凭 prepared_baseline 自动增加正常效果分母。

公开身份：baseline_tree_sha256 为 5f50f5953e6df2428de5edc9098c8e10c4335db1c6d198318c9c1deee59f4d3e；准备者来源映射清单摘要为 16593eccf8a40badc8c6826af94cda9205a52bd0a4ae9c6da6bf796dbbdc621c。完整源码和证据仍只在 private；这些摘要是接收身份，不是假装主流程重新计算了私有内容。
