# 质量门禁价值与验证成本：存量候选回顾设计

- 日期：2026-10-24。
- 状态：设计完成、输入身份核对通过；完整回顾分析尚未实现/执行。
- 实现基线：`3c1e1b1`。
- 前置：[研发对齐与公共命令取证](2026-10-24-rd-alignment-review.md)。
- 当前交付：[五项固定候选清单](../experiments/gate-value-review-v0.1.0/candidates.json)。这是存量回顾的输入登记，不是新生成协议或严格留出冻结。

## 1. 要回答的问题

系统已有批量执行、独立质量判定、交付和审计闭环。下一项要补的是可解释的价值证据：**同一候选已有构建/测试通过记录时，完整门禁额外阻挡了什么，又留下了什么误拒或待确认成本？**

其次记录已发生的验证命令数量及耗时，说明这些证据的执行开销。更高的自动成功率、推广到新仓库的接入成本、实际人类审核耗时仍需另有证据，不能由本回顾推出。

## 2. 方案选择与范围

| 方案 | 当前可回答的问题 | 得失与本次选择 |
| --- | --- | --- |
| 再运行一次真实生成 | 当前实现下新候选的迁移结果 | 有随机性与新增消费，无法独立解释门禁价值；本次不选 |
| 对保存候选重跑当前门禁和独立构建/测试分支 | 当前版本对固定候选的直接对照 | 需要固定新环境/材料、承担多配置和实际超时执行成本；适合后续检验当前规则，当前不先做 |
| 在同一批历史候选上比较原报告中的构建/测试证据与原完整结论 | 历史门禁的新增拦截、未知和误拒，及已记录的执行开销 | 不增加生成成本，能同时展示收益和局限；选择先做。不是独立运行的消融或新版本效果试验 |
| 新仓库接入计时或人员审核对照 | 接入/实际审核成本 | 必须有真实工作和活动计时；不能从提交跨度或助手回复时间恢复，另列后续条件 |

优先从存量材料提取完整、可核查的事实，再决定是否值得新执行。只为让已见候选通过而重复跑当前门禁，增量价值不足。若历史证据缺少必需命令/测试事件，结果保留证据不足，不通过重新执行填进历史记录。

本项不改质量规则、Profile、原候选、正式 round 指标或 M3—M5 验收条件，不构造新错误样本。没有新模型调用、Docker 执行或付费额度。

## 3. 固定输入与暴露关系

选择已完成真实生成的五个原候选，均在本设计前已见，不能称盲选或未见：

| 层次 | 样本 | 原完整门禁 | 既有助手复核给出的关键信息 |
| --- | --- | --- | --- |
| 2026-10-22 四任务 | Goddd | NeedsAttention | 测试保留 pass、变更覆盖 inconclusive；语义真值仍未知 |
| 同轮 | Translation | NeedsAttention | 测试保留/变更覆盖/交付依据 pass，两配置必需 |
| 同轮 | Workouts | ReadyForReview | 三项 pass，common 是必需依赖 |
| 同轮 | GHCLI | Rejected | 变更覆盖 pass、交付依据 fail；拒绝依据误判 |
| 2026-10-23 单任务 | GHCLI 响应丢失 | NeedsAttention | 变更覆盖 fail；有返回值变化诊断，旧自动参考仍 pass |

逐项 Run、候选/基线/规范/实现材料摘要和 report/reference/review 的路径及原文字节摘要写入固定清单。四任务采用交付包内保存的原材料，后续单任务采用原运行及独立结果目录；数据不随 Git 分发，缺材料时必须报告缺失。

两个 GHCLI 候选属于同源组，两个轮次使用不同历史实现。先分层逐项报告，不将五项合成总体成功率、错误放行概率或五个独立仓库。生成成本仍引用原实验原分母，禁止复用 `round` 正式计数函数把回顾投影伪装成一个新生成轮次。

现有自动参考/助手复核作为有局限的判据：Goddd 的未知不能变成正确；GHCLI 原拒绝依据错误不能变成候选已证实语义错误；返回值诊断来自事后观察，不能声称冻结参考当时发现了它。准备/开发/复核之间存在暴露和共同设施，不能证明普遍正确性。

## 4. 对照的确切含义

### 构建/测试证据视图 B

这是从**同一原报告和原日志**提取的受限证据视图。记为 `supported / failed / insufficient`，不使用 ReadyForReview 命名，也不进入真实调度或放行。

- supported：基线健康；所有必需配置及模块的候选构建/测试完成，必需测试身份与包终态齐全，无取消、OOM、输出截断或设施失败。
- failed：有可归因的候选构建或测试失败，保存具体命令/事件；设施错误不能归入业务 failed。
- insufficient：缺输入、必需配置/模块、日志、事件，身份不匹配，或无法确定测试是否实际执行。

宿主 Profile 的必需测试身份和构建配置用于确认检查完整性；不消费 test_preservation、request_scope、semantic_behavior 等额外检查的结论来改善 B。B 通过仅意味着上述构建/测试证据充分；候选可能改弱测试，因此测试保留仍属于完整门禁的增量义务。

命令映射显式按场景列出：Goddd baseline/candidate build 与 test；Translation 的 default/rpcx_alternate 各 baseline/candidate list、build、tests；Workouts 加 common-build/common-test；GHCLI baseline/candidate build/test。还须核对归档 Profile，未知名称不能靠模糊匹配自动归类。必需事件沿用现有严格事件读取机制；必要时使用独立的只读校验入口，不修改原报告。

B 的日志本来由完整门禁准备和执行，部分测试可能依赖它的准备步骤。因此这里不能声称“独立只跑 go test 也一定如此”，也不能从视图 B 推断一个简化实现的实际速度或成本。若要得出该结论，必须另做独立执行分支。

### 完整门禁视图 G

从绑定的原报告读取原始 verdict、检查状态、条款、证据和 finding。原报告 Rejected/NeedsAttention 不因后续规则变化改写。审计验证身份与一致性，独立参考和实际复核用于解释候选及判定依据；审计 pass 本身不认证语义正确。

若要引用当前版本的已完成校准，另列“事后修正”列，引用已有记录，不把它覆盖 G，也不算新迁移结果。本次无需重跑当前门禁。

## 5. 原始计数与错误分类

优先产出逐项表：`B / G / 自动参考 / 迁移变更判据 / 交付依据判据 / 具体原因 / 来源引用`，然后按两个历史层次列原始数量。

| 计数 | 条件与解释 |
| --- | --- |
| 构建/测试不能识别的已知错误 | B=supported，既有可定位诊断或充分复核确认 migration/test 错误；只计具体反例，不推断总体比例 |
| 完整门禁的额外阻挡 | B=supported 且 G 不为 ReadyForReview；同时分成已知错误、未知、复核支持、交付依据错误，不把所有阻挡称为成功拦截 |
| 直接违规定位 | G=Rejected 且 finding 能绑定实际已确认的违规；仅 unknown 不算具体定位 |
| 待确认造成的阻挡 | G=NeedsAttention；按复核结果细分正确/错误/未知；这是工作量入口数，不是审核活动时间 |
| 错误拒绝依据 | G=Rejected，而已有复核确认其所援引违规不成立；不和语义错误放行混为一个指标 |
| 放行后未知/确认错误 | 单列数量与来源；参考未知不默认正确，样本中零观察不能证明总体零风险 |

对于后续 GHCLI，原 G=NeedsAttention 只是安全阻挡，不能记作“原门禁识别响应丢失”；定位该违规属于后来的新门禁。对于旧 GHCLI，必须同时显示误拒成本，不能因后续修正而在回顾中隐藏。

## 6. 成本口径与缺口

从原门禁 Commands 提取：命令数、必需构建配置数、逐命令 duration_ms 和分类汇总。明确区分构建/测试视图所引用的命令、额外验证命令和无法归类项，所有项都回到原 command/日志证据。

- `recorded_command_ms_sum` 是命令墙钟区间的和，不是 CPU 时间、批次墙钟或独立分支反事实耗时。并发的任务不能直接相加当批次时间。
- 命令之外的复制、快照、类型检查准备、哈希/规则运算、发布和审计耗时没有完整计时，不把总和称为完整验证成本。
- 真实 30 秒到期探针包含刻意等待；环境、冷编译和两个历史版本不同，不能拿比值归因于公共化改进。
- 无模型调用的回顾，其新增 API 请求为零；原生成 Token/金额仍按原实验记录，不重新摊成每个证据的价格。
- 接入成本分为来源/依赖准备、可信业务判据/测试适配、Runner/审计接线及交付验证。现有提交和 worklog 只可定位工作，不可推算活动工时。后续真实接入才做分项活动计时。
- 审核成本只列“需要确认的项及材料位置”；实际人类活动时间保持未知。助手耗时和机器运行时间不替代人类计时；未来若比较阅读效率，需先固定任务、参与者、正确性判据与分组/阅读顺序，避免同一人先读完整证据再假装盲读补丁。

## 7. 实施边界与验收

下一单元为只读回顾实现，优先调用既有 audit、事件校验和参考/复核消费机制，不新增框架、付费入口或通用性能平台。完整回顾与正式 `round` 分母分开。

| 验收条件 | 方法 |
| --- | --- |
| 五项全保留，身份明确 | 固定清单/原报告/参考/复核与实际候选摘要核对；缺项也输出一行，不挑最好 Run |
| 不凭 pass 文本计通过 | 核对命令、原日志哈希、必需配置/模块及测试事件；删除/改日志、换候选、缺配置/测试事件均变 insufficient 或输入冲突 |
| 解释局限与收益 | 输出未知的 Goddd、已知返回值错误和 GHCLI 误拒；每个判断有候选/条款/证据定位 |
| 成本可追溯 | 各命令只分入一个执行类别，未归类不丢弃，分类和等于完整命令数量/时间和；CPU/人类时间不伪填 |
| 原材料不变 | 执行前后核对消费源摘要；故障注入只在独立副本，输出独占新目录 |
| 可复核交付 | JSON/Markdown 与数据缺失诊断；明确 seen/historical 标签，不更新原四任务 1/4 或后续单任务 0/1 |

先完成输入认证和视图 B，再输出逐项比较与命令成本，最后做副本负例和原文件保全。遇到旧格式缺证据就报告缺口；若为了得到完整 B 必须重跑所有候选，先交付“历史不足”的结果，再单独决定当前版本重跑，不扩展本单元。

本回顾完成后停止：根据实际结果选择一个改进目标，可能是某类可证明缺口、验证开销或更有代表性的开发任务。没有新问题依据时不自动追加模型生成、不继续扩展 GHCLI。严格留出与原人员验收继续单列。

## 8. 本轮实际工作与检查

本轮完成设计及五项输入可用性核对：核对实际候选全树摘要、原报告内全部 Evidence 文件摘要、Run/候选身份、复核对参考报告的绑定。初次核对误把 review.report_sha256 理解为运行时 report 摘要而失败；读取 round.attachReference 后确认其绑定的是独立 reference.json，修正核对脚本后五项通过。没有修改旧数据，也没有把该读取脚本错误当成材料损坏。

本地核对结果为 `runs/gate-value-design-01/inventory.json`。五项分别核对 33/66/79/41/34 份门禁 Evidence；这只是身份/存在性检查，未完整重算测试事件、参考判定或审计，不提前填写 B 的 supported，也不发布增量收益结论。初步读取发现五个报告的 build/baseline_tests 文本均 pass，完整回顾仍须按第 4 节验证。

仅修改设计文档和输入清单；未运行 Go 测试、Docker 或模型服务，未创建新评测结果、修改正式参考或回填人类耗时。下一步按第 7 节实现只读回顾并验收。
