# Translation 诊断反馈的单任务真实观察设计

- 日期：2026-10-24（Asia/Taipei）。
- 状态：设计及协议准备已确认；用户另行授权后唯一真实尝试、轨迹分析、固定参考、实际助手复核及收尾完成。原 Run 为 Failed / limit_reached，没有最终质量判定；[实际报告](../experiments/2026-10-24-translation-diagnostics-real-model-01.md)。
- 已有实现：`2a8c8ee`；[诊断首版与验收](2026-10-24-generation-diagnostics.md)。
- 本步目标：确定一次有限观察的问题与判据，按确认设计固定执行材料；设计与准备作为一个工作单元提交。实际条件见[协议 v0.1.0](../experiments/translation-diagnostics-dev-v0.1.0/README.md)。

## 1. 要回答的问题

脚本化验收已经证明“收到诊断→编辑→再次检查→提交→独立门禁”的机制成立，但脚本事先知道如何修改。当前缺少真实生成对话的证据：Agent 会不会使用 baseline/migration_check，收到具体位置后会如何修改，最终候选是否保留原测试要求。

本次主要观察**工具的实际使用与反馈后的行为**，同时报告候选质量、独立复核与消耗。单次结果不能证明成功率提高，也不能区分基线可读、提示、新工具和模型随机性各自的作用。

选择 Translation：它有已确认的原断言削弱案例，测试结构诊断能定位相应声明，输入和双配置参考已具备。Workouts 的已知问题是生产期限边界，当前工具并不覆盖；重复观察它无法直接回答测试结构反馈是否被使用。选择依据在生成前固定，不根据新候选是否成功换样本。

## 2. 方案与取舍

优先级：获得可核对的真实使用轨迹、控制消费与范围、保持独立判定，然后才扩大样本和做效果归因。

| 方案 | 收益与限制 | 本次选择 |
| --- | --- | --- |
| **一次全新迁移，自主选择是否使用工具** | 保留真实规划行为，费用范围小；可能没有错误或完全不调用工具，无法观察修复收益 | 采用，允许结果没有修复机会 |
| 提示中要求必须使用诊断 | 更容易得到反馈轨迹，但改变生成策略，回答的是受指令使用是否有效 | 暂不采用；未使用时作为后续独立方案再讨论 |
| 从旧错误候选开始修复 | 稳定提供已知问题，较容易观察定向修正；输入与原样迁移不同，且主流程已知答案 | 暂缓，不用它代替本次自主迁移 |
| 新建诊断开/关的成对生成 | 可开始比较两种配置，但单对波动仍大，调用上限至少翻倍 | 若本轮得到具体可研究假设，再设计重复对照 |
| 再跑四任务或先扩充生产诊断 | 覆盖更多结构，投入也扩大；尚未知道新增测试反馈是否被使用 | 本轮先回答有限问题 |

本轮初始提示、工具说明和预算提醒沿用固定实现；启用 DiagnosticLimit=2，不追加“必须调用”的提示，不提供旧错误位置、旧候选、参考补丁或协调者的修复建议。baseline 保持可读。Agent 可以不调用、一次调用、两次调用，或带未解决问题提交。

| 项目 | 拟定范围 |

| 请求与 Token | Campaign 和 Target 同为最多 40 次生成准入、2,500,000 Token（含未知消耗的整笔保守占用）；Loop 最多 40 次 Complete 尝试 |

## 4. 轨迹观察与判定

完整保存原 Agent 对话、工具结果、逐次候选快照及原 Run/账本。仅统计助手提出的 tool_calls 会把未执行的批量请求算成调用，因此必须结合对应 ToolResult、Loop 计数及宿主诊断引用。

| 观察项 | 证据及记录口径 |
| --- | --- |
| 工具是否被提供 | 分开记录配置启用及实际提供；核对工具 schema、DiagnosticLimit、实际 Plan/Input，以及有回复请求的 Messages+Tools 摘要；尚未调用模型时实际提供记未知 |
| baseline 是否使用 | 实际 list_files/read_file/search 的根及结果；区分仅列目录、读取原测试、读取生产文件 |
| 诊断是否执行 | 分列模型提出次数、有对应结果的尝试数、成功发布报告数、参数/专项额度错误数；每份成功报告绑定其完整候选 |
| 反馈是否进入后续请求 | 核对后续模型请求及预算绑定/回复；只有工具输出而没有后续请求时，记“已生成反馈、未观察到模型继续处理”，不算已理解 |
| 反馈后有什么修改 | 按 tool_call_id 顺序对照实际 replace_text 的成功结果，关联诊断声明位置及后续候选；区分同一声明、其他测试、生产代码和无修改 |
| 检查状态如何变化 | preserved/violated/unknown 原样保留；第二次结果是否针对修改后的候选，最终候选是否又发生变化 |
| 最终约束是否满足 | 原门禁、固定参考、实际源码复核分别列出，特别核对 TEST-001 的断言/表数据/helper，不用结构 preserved 或参考测试 pass 代替完整复核 |

后续准备一个本地离线分析脚本即可，不新增产品模块。它从冻结基线在内存中重放日志中**成功执行**的 replace_text，核对相对路径、旧文本唯一匹配及新文本；在每次诊断点比对完整候选摘要，并核对最终 Run 候选。只处理文本与文件身份，不执行日志中的命令或代码。缺记录、重放不符、原文无法唯一匹配时停止推导相应行为链，标为不可核对，不靠模型总结补齐。

“诊断后发生相关修正”只表示时间顺序与修改位置有证据，不宣称诊断造成修复。unknown→preserved 也不直接等于候选语义正确。模型自述“已修复”仅作为自述保存。

后续请求的身份指宿主 Complete 输入、对应预算准入与已保存回复；消息/工具摘要不是 HTTP 字节摘要，也不证明服务端已经收到或理解。只有失败调用而没有后续回复时，模型是否处理了反馈仍记未知。

## 5. 结果解释与后续选择

| 本次实际情况 | 可以报告什么；后续方向 |
| --- | --- |
| 不使用诊断 | 记录工具可用但未使用，以及是否使用 baseline；无法评估反馈后的修复。再权衡生成提示或受指令使用实验，不立即扩展检查范围 |
| 使用时已经 preserved | 观察到主动核对，当前没有原测试结构修复机会；不能宣称防止了断言削弱 |
| 收到 unknown/violated 后有相关编辑 | 记录可重建的状态/改动链，并按最终参考/复核判断结果；若仍错误，定位反馈理解或修改问题 |
| 收到反馈但无后续请求 | 分列预算、取消、模型/执行错误等原因；没有进一步处理机会，不能据此判工具无用 |
| 修改原断言但未诊断，或诊断后再次改坏 | 保存遗漏时点；先讨论提交前生成引导/检查时机，而不是调整最终门禁以放行 |
| 全部结构 preserved，仍 NeedsAttention | 按最终具体缺口记录，考虑生产边界检查或证明支持；不把测试诊断视为覆盖全部迁移 |
| 材料、能力或环境在生成前不符 | 完成启动拒绝记录，生成数为零；修正准备需另行说明，不自动复用本版启动许可 |

N=1 为事前计划目标，实际 Run R=0/1 单列；生成前停止记计划未交付。执行失败、Rejected、NeedsAttention、ReadyForReview 分开。S 仅在原 Run Completed/ReadyForReview 且完整参考/实际复核 pass 时为 1；放行数 A=0 时错误放行率无定义，参考或复核未知时不补成完整通过。

主要展示原始计数、轨迹和最终约束，不报告总体提升。旧四任务、旧 Translation 与本轮输入暴露/实现条件不同，作为历史背景单列，不合并分母或做因果比较。所有失败及未知保留，不因没观察到修复就追加第二个 Run。

费用报告实际准入/拒绝、已知输入/输出 Token、未知/在途占用、总工具及诊断次数、Run/宿主墙钟和已记录命令耗时。当前诊断报告没有逐次耗时字段，对话也没有逐条工具时间戳，因此**不能精确拆出诊断耗时或反馈新增成本**，相应项标未测量；本步不为一个观察增加计时系统。参考/复核处于生成批次外，另列；实际金额、人类活动时间未知就标未知。

## 6. 确认后的准备与执行边界

1. 先准备一份新版本协议：固定 batch/enrollment、数据分区、实际复核者、源码/二进制、模型历史期望、实际本地环境及预期计划；增加可重放轨迹分析脚本，不改变生成提示或质量规则。复用旧启动器的核对/停止流程，明确改成单 Target 和 12 分钟，不照搬旧四任务常量。
2. 本地离线核对：启用字段确实进入实际计划设置摘要；harness --check 与启动器 --check 均零能力查询/零生成，输出及启动收据目录独占；分析脚本使用已保存的受控修复轨迹校准，区分没有后续模型请求的情形。材料固定后，设计与准备/校验作为同一工作单元提交。
3. 展示可审查协议与限额，再取得**本版一次外发/消费授权**，才读取 .env 的 DEEPSEEK_API_KEY，发起一次 Models GET 并发送新任务代码/规范/SDK 与工具交互。之后按原候选运行独立参考及实际复核，完成汇总、轨迹分析、审计、补丁重放、审核导航、来源保全和精确资源回收；不手工改候选或回写原判定。

生成结束前不运行独立参考，不将评测答案、旧补丁或协调者诊断反馈给 Agent。生成后所有有可认证候选的尝试都进入参考/复核，即使 Run 执行失败也保留其候选诊断，但不能事后晋升为原自动成功。没有可认证候选时相关检查记不可评。

原单次许可已消费，设计确认与本次准备授权不包含真实外发。方案确认、执行材料冻结与本版真实外发授权是不同步骤，不将时间经过或前次授权当作新许可。首次结果完成后再讨论研发选择，严格留出和原总体验收缺口继续保留。
