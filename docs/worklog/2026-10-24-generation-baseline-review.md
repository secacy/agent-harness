本次只读核对原 `artifacts/agent.json`，下标为 Messages 的零基下标：

| 来源 | 实际轨迹 | 能得出的结论 |
| --- | --- | --- |
| Translation / rpcx-agent-1712004754 | 消息 70 的 replace_text 将原期限断言下界从 29 秒改为大于 0；76/79 才首次 build/test；80、92 的两次 test 均通过 | 修改发生在测试失败反馈之前，不能解释成修红测试时被迫改断言；生产 30 秒正确仍不满足 TEST-001 的原测试保留要求 |
| Workouts / rpcx-agent-4062530435 | 消息 64 在 handler 新增两个超时 helper；75/107 的 test 均通过；100、104 自述检查逐调用期限，114 正常提交 | 模型做过自检，但没有覆盖规范 TIME-001 指定方法的直接调用边界；不能把模型自述算成证明 |

两份任务的完整规范都已在初始用户消息中。Translation 使用 24/40 模型调用，Workouts 使用 29/40；均正常提交，没有预算耗尽记录。证据不足以判定预算是这两项错误的主要原因，也不足以证明提示修改一定有效。

[生成入口](../../scenarios/rpcx/runner/run.go)现有根为候选、规范和 SDK/允许依赖。修改前的源代码可能在对话中，但模型没有直接读取不可变业务基线的工具根，也没有 diff 工具。[go_check](../../internal/repotools/check.go)只反馈构建/测试；独立 Evaluate 在模型停止、候选固定之后执行。

## 2. 方案取舍

优先级：减少与迁移无关的行为改变；保留语义门禁和未知分类；维持已有单 Run/预算/恢复契约；之后才比较自动交付率与成本。

| 方案 | 对当前问题的作用 | 代价与本次选择 |
| --- | --- | --- |
| 扩充常量、parent 别名和 helper 的自动证明 | 有机会减少 Goddd/GHCLI 的未知 | 无法纠正 Translation 已削弱断言或 Workouts 错误期限边界；继续围绕已见候选扩规则。本步暂缓 |
| 只追加“遵守规范”提醒 | 改动小 | 规范已经明确，Workouts 也曾自述核对；重复提醒缺少可操作的原文对照。不单独采用 |
| **提供只读基线＋具体对照要求** | 编辑后可重新查看原断言、错误链和调用边界；提示检查每个规范要求的 RPC 入口 | 需要额外读文件/比较，可能增加 Token；自检仍可能漏错。选择为本次有限改进，不当作新的验证门 |
| 新增提交前语义检查工具 | 可给出机器反馈，Workouts 的直接调用失败有潜在价值 | Translation 目前仅得到 test_preservation unknown，不能直接投射成“断言削弱”；需定义公开诊断、快照绑定、检查费用与可见材料。待本步之后另行比较，不能直接暴露独立参考 |
| 完整门禁反馈后自动修复 | 可利用确认的违规触发后续修改 | 现有 Run 只有一个候选/验证终态，直接再次 Loop.Run 会重置循环计数；还需保存每轮候选与验证、累计时间/工具/请求、控制反馈白名单及重入/恢复。不纳入本单元 |

这不是关于所有迁移的长期架构决策，暂不新建 ADR。改选条件：若后续受限开发观察中模型已读取基线仍反复破坏约束，或检查来源不足以定位错误，应优先设计可核对的公开诊断；不要继续无限加长提示。若候选普遍经独立复核正确而被同一有限形式阻挡，再以正反例权衡证明范围。

## 3. 实现契约

1. `baseline` 只映射 `baseline/<RepositoryName>`，来自本 Run 已认证的准备副本。复用 list_files/read_file/search；不暴露整个 Run、Profile、宿主材料、oracle、参考答案或历史候选。它是公开任务的原输入，不是评测答案。
2. replace_text 仍仅能写 workspace；不新增写根参数。路径穿越、未知根及符号链接规则保持。baseline 不加入 go_check 的执行挂载，构建/测试仍针对候选；文件工具只读限制不冒称宿主文件系统沙箱。
3. 通用迁移提示要求在提交前对照基线：原测试断言/表数据/helper 的必要适配、行为/错误和返回值，以及规范指定的每个 RPC 边界。存在超时要求时检查直接调用的 parent/期限/资源释放；不把 30 秒要求强加给不含 T3 的规范，也不要求所有代码套用同一 AST 模板。
4. 提示倡导仅做必要修改；测试成功不替代约束核对，无法核实的内容列为未解决。模型可正常提交包含未知的候选，不新增强制自评通过字段或无限检查循环。最终总结仍为自述，质量只由提交后的独立门禁给出。
5. 复用原请求/工具/总时限、预算通知和持久化对话。新增读取占既有工具次数；不追加额度或二次生成，不改变候选/报告/schema、冻结 Profile/规范或旧实验结论。

先写设计与范围，再做最小实现和上述验证；作为一个可验收单元提交。此阶段不执行新的真实模型实验。以后若观察效果，需要冻结新生成配置、一次尝试及成本上限并记录全部结果；不能拿本次脚本模型测试声称减少了两项真实错误，也不能把两个经复核支持的 NeedsAttention 算作自动成功。

## 5. 实际实施与验证

新增 `TestGenerationBaselineComparisonIsReadOnly` 经真实文件工具完成编辑→读取基线/候选→列目录/搜索→四种越界/写入拒绝，再经受控后端核对候选命令挂载。模型随后故意返回错误，Run 为 Failed、质量为空且没有 Validation；基线和原夹具完整摘要不变。基线事件和命令结果由替身提供，该测试不证明真实构建通过或模型会遵守自检建议。
