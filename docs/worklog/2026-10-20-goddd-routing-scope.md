# Goddd：命名期限常量与构造器兼容参数的范围证明

- 日期：2026-10-20
- 状态：设计与最小结构原型完成；生产规则未实现
- 代码基线：dc939a3
- 对应里程碑：[M3.4](../MILESTONES.md#m3多仓库批量闭环)
- 前置：[mock/context 有限适配验收](2026-10-20-goddd-context-adaptation.md)
- 当前结论：采用两条场景内的局部结构证明，保留完整剩余结构、类型和行为检查；不继续枚举整文件模板组合

## 问题与目标

上一单元的新门禁已使原 Goddd 候选副本的 test_preservation 通过，mock 缺口消除。其余七项检查通过，仅 request_scope 对 `routing/proxying.go` 保留 unknown，实际多出：

```go
const fetchRoutesTimeout = 30 * time.Second
// RPC 方法首部：
ctx, cancel := context.WithTimeout(ctx, fetchRoutesTimeout)
defer cancel()
// NewProxyingMiddleware 首部：
_ = ctx
```

已有类型报告已记录该直接 RPC 为 covered、fetch_routes、timeout_ns=30000000000；可信行为也已通过。缺口并非“尚未证明期限是 30 秒”，而是完整生产结构检查尚未解释新增声明和构造器语句。不能仅凭类型/行为通过就绕过 SCOPE-001。

目标是在原约束下解释这两类变换，并保留其余声明、映射和构造器逻辑的比较。依据为 TIME-001—003、CTX-002、BEHAVIOR-001、SCOPE-001；规范明确允许保留构造器兼容参数，但不得将其作为请求 ctx 来源。不要求真实候选最终放行，不扩展 Translation、一般常量提取或通用无副作用分析。

## 方案取舍

优先维持证明边界和可追溯性，再减少由有限表示差异造成的人工确认。不能只为这个已见候选增加一个恰好同名的特例。

| 方案 | 当前问题上的得失 | 选择 |
| --- | --- | --- |
| 保持 unknown | 无新增复杂度，但这两项仍需反复人工确认；已有材料足以尝试有边界证明 | 保留为越界时的默认结果，不作为唯一后续工作 |
| 类型/行为通过就忽略新增 const 和赋值 | 最少代码，但未使用常量、业务常量、构造器调用/重绑都可能被一起隐藏 | 不采用 |
| 继续生成整文件固定变体 | 与上一单元一致，但常量名、是否使用常量、是否保留空读形成组合；固定 fetchRoutesTimeout 名称会针对样本写规则 | 不采用为本问题的主要实现 |
| 扩大隔离类型分析，输出任意声明绑定与副作用证明 | 可支持别名、跨文件、任意常量表达式；当前 Report 只输出 RPC 事实，新增协议和全套分析成本明显更高 | 暂缓，有重复需求时重评 |
| 校验有限 AST 前置条件，在比较副本中消去已解释节点，再比较完整剩余结构 | 不增加模板组合，能支持不同新常量名；接受表达式、作用域和位置限制，越界仍 unknown | 采用，类型与行为仍独立必需 |

这一步没有否定上一单元的固定模板：mock 改变回调签名和转发，必须完整匹配受信形式；本步只处理能够局部证明的额外声明和一次参数读取，不忽略任意 ctx 变化。

## 具体支持边界

### 命名期限常量

仅在 `routing/proxying.go` 中支持一个额外的包级 const 声明：单个名称、单个值、无显式类型，值的 AST 正好是 `30 * time.Second`。允许只含该声明的 const 块；不支持多声明、iota、继承表达式、任意等值计算或显式类型转换。常量名可以变化，但必须是全新的未导出标识符，不能是 `_`。

必须同时证明：

1. 已认证基线的全部生产 Go 文件中不存在该标识符；保守扫描声明、局部、字段、标签等，不猜测名称等价。
2. 候选全部生产 Go 文件中，该名字只出现两次：当前 const 的声明节点，和目标 RPC 方法开头 WithTimeout 的第二个实参节点。两个节点的位置必须对应，不能只统计字符串次数。候选测试不参与生产名称证明，原测试逻辑仍由独立检查约束。
3. 目标是唯一的 proxyService.FetchRoutesForSpecification，前缀符合限定的 ctx/cancel 派生与 defer 形式。名字不是遮蔽变量、另一个方法或普通业务参数。额外声明/引用、跨文件使用或碰到无法解析的生产文件均不提供该证明。
4. 从比较副本移除该新增 const 后，其余导入、声明和业务结构须与现有宿主适配一致。context/time 的实际导入和绑定没有获得自由替换许可；候选增加遮蔽、改导入或新文件不能靠此证明消失。

只消去声明，不改原候选文件。原有期限前缀的有限比较继续存在，migration_completeness 仍负责标准库对象、父 ctx、实际常量值、派生及释放绑定，semantic_behavior 仍负责真实观察。该局部证明不代替二者，也不凭已有 TimeoutNS 值断言所有新增声明合法。

采用生产文件标识符扫描的理由是：当前只支持一个全新名称、两个明确节点，出现遮蔽必然增加声明或改变剩余结构；可以保守拒绝而不扩大共享类型协议。代价是同名字段/局部等不一定有语义影响的写法也会 unknown。支持任意别名、跨文件常量或更宽表达式时重新选型，不继续堆词法例外。

### 构造器参数读取

只支持无接收者、签名保持原适配的 NewProxyingMiddleware，其第一条语句是精确的 `_ = ctx`：一个左值、一个右值、赋值符号 `=`，右值是参数标识符本身。

前置条件：宿主适配已移除长期 Context 字段及其初始化；适配后构造器体不再使用 ctx；候选仅有这一次参数读取，删除它后的完整构造器和文件剩余结构不变。参数类型与原签名一致，因此没有把其他对象或表达式当成参数读取。只在比较副本中删除这条语句。

不支持 `_ = ctx.Err()`、`_ = someFunc(ctx)`、ctx 重绑/捕获/保存、字段读取、多个空读、位置移动或其他方法中的类似语句。尤其不能忽略 `_ =` 右侧的函数调用：返回值虽被丢弃，调用仍可能有行为。构造器 ctx 与请求 ctx 的不同来源仍由范围与运行时探针核对。

## 接入与证据安排

先尝试现有 canonical/forwarded 完整匹配；只对 routing 文件未匹配时执行上述两条局部证明。两项可以单独出现，也可以一起出现，不生成四份整文件模板。证明后仍需完整剩余结构匹配，局部前置条件成功不等于整个 request_scope pass。

拟在 goddd 包内增加普通的 routing 范围检查函数，输入为宿主适配、完整基线及候选快照，返回匹配与局部事实。没有新插件、规则 DSL 或共享分析接口。当前 `analysis.Report` 已能证明实际期限，本单元不改变它的协议和 worker。

新增 `routing-scope.json` 保存 schema_version、规范/基线/候选与工具绑定、两侧原文件摘要、声明和引用的位置/摘要、构造器参数及空读位置、规则/原因、剩余结构比较结果。原始 Candidate 摘要始终来自原文件，归约只发生在 AST 副本中；不执行归约后的代码，也不把它作为迁移补丁。

`scope.json` 的 Findings 引用该新 Evidence，只有局部事实和剩余结构都充分时才解释这个文件。`adaptations.json.production_matches` 继续只表示固定模板直接匹配；归约证明另以独立材料和原因记录，不能冒称宿主在读取候选之前生成了同一份期望变体。证据发布失败返回 error、无质量 verdict。

不改变 quality.Policy 的必需集合和 fail/unknown 优先级。范围检查可先于类型检查完成；它不预填后续类型结果，最终仍要求独立检查全部通过。Profile、规范及冻结数据保持原内容，新源码/工具材料身份单独保存；历史实验不升级。

## 最小原型与限制

`runs/goddd-routing-scope-design-01/` 中复制了现有 adapt/syntax，仅修改包名和摘要函数引用，另外编写比较副本的诊断归约。只解析 AST，并使用现有有限指纹比较，不执行候选、Docker、模型或修改生产规则。输入来自前次已保存的原候选及认证基线。

15 个结构对照通过断言：两项同时存在、分别存在、均不存在、换一个新未导出常量名共五个正例；5 秒、var、导出名、其他文件增加使用、构造器调用/重绑/捕获、请求映射变化、额外常量、响应映射变化共十个反例仍不匹配。某些反例会得到局部事实，但完整结构比较仍失败，不能将其事实数当作通过数。

结果与原因记录在 results.json，原型源码在 probe/。它只验证可表达性，尚未实现所有签名/位置防御、证据发布、失败分支与质量聚合。反例的“不匹配”不是最终 Rejected；本轮没有为任何候选产生新质量判定，也没有重跑真实模型。

## 下一单元实施与验收

作为同一项 routing 范围证明工作实现与提交：先写局部检查和边界测试，再接独立证据与完整比较，最后执行校准。不要逐个模板或小函数提交。

| 验收主题 | 正反例及完成条件 |
| --- | --- |
| 名称与声明 | 新未导出名正例；已有名、导出名、别名/字段/局部遮蔽、额外声明、var、类型/iota/多值均不被消去 |
| 实际使用范围 | 声明及期限参数精确两处；未使用、其他文件/函数/RPC 使用、请求参数使用、局部重绑定仍 unknown，不以总出现数冒充节点对应 |
| 构造器读取 | 无空读/精确一次首部空读正例；函数调用、字段访问、捕获、重绑、保存或移动空读均不得被消去；包含 nil/取消/有值兼容 ctx 的实际对照 |
| 剩余结构 | 新增 helper、改请求/响应/错误处理、其他方法、语义指令仍不匹配；不忽略整个 const 块或整个构造器 |
| 其他门禁仍有效 | 错时长、父 ctx、提前取消、删除断言和保护路径反例仍按原证据拒绝；行为通过但结构越界仍 NeedsAttention |
| 兼容与完整交付 | 六项冻结校准、前次 mock/context 正反例和其他场景回归；独立 Docker 正例、明确错误、仍未知对照，保留真实到期及资源回收 |
| 证据与失败 | 原 Candidate/文件摘要不变，局部事实与实际节点可重算；材料缺失/写失败无最终 verdict；完整剩余比较失败不能被局部证明数掩盖 |
| 原样候选开发校准 | 单独副本使用新门禁完整 Evaluate，只有全部必需证据充分时才可能 ReadyForReview；不得预先以此作为设计成功或回写原结果 |

之后对原 5907 份 Campaign 材料和冻结输入做前后摘要核对；新校准属于已见开发样本，不增加原实验自动成功数或补填人类复核。M3 和独立留出依赖不因结构扩展自动完成。

本设计没有形成需要替代已有 ADR 的长期架构选择；依然遵循 [宿主规则所有权](../adr/007-host-owned-task-profiles.md)和[绑定证据聚合](../adr/002-evidence-bound-quality.md)。若未来需要通用常量/绑定事实或证明组合成为重复负担，再单独比较并记录长期选择。
