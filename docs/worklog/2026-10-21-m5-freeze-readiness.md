## 1. 本步解决什么

[新应用接入](2026-10-21-isolated-application-integration.md)已经完成校准和最终独立核验，本步不重做同一实现的评审。需要决定：下一轮究竟测哪些任务、能回答什么，以及哪些缺项真的阻止运行。

当前工程优先级是形成完整、可讲清楚的交付。原严格未见留出尚未具备；新应用虽由隔离 Agent 准备，但已经进行参考、门禁和正反例校准，也发生过参考契约修订。主流程只接收元数据，不足以把整个准备/接入过程认定为严格未见验证。

## 2. 范围选择及依据

优先回答“固定后的当前 Harness 在已支持的不同输入上，能自主交付什么、判断是否可靠、花费多少”，同时保留检验未见仓库泛化的原目标。

| 方案 | 能回答什么 / 接受的代价 | 决定 |
| --- | --- | --- |
| 等到另有严格未见、独立人员保管的样本再运行 | 最接近原 M5 留出目标；仍需新材料与接入，当前无法据已有回执宣布就绪 | 保留为原验收缺口，不作为本轮唯一推进路径 |
| 只重跑三个已见开发样本 | 无需新增 Profile 准入，能比较当前实现；新应用仍只有手工校准，没有自主迁移观察 | 不选为首轮范围 |
| 三个已见开发样本＋一个隔离准备后已校准的应用样本 | 覆盖现有四个受支持输入，并检验新布局的实际 Agent 链路；必须补协议准入，不能声称未见泛化或独立人类盲审 | **采用；发布为首轮固定样本评测** |

选择四个的理由是它们已有可复用的基线、可信 Profile 和参考，不需要再选源或从头开发验证器。新增代码只解决新应用的正式协议资格，不能借此放开任意目录或 heldout。若该资格无法在原安全边界下成立，先停止冻结并记录原因，不在看过生成结果后删掉该 Target。

这是一次实验范围选择，记录在 worklog；不新增长期架构 ADR，也不修改原 M5 的留出验收标准。

## 3. 本轮拟固定的任务和方法

| 报告分层 | Target / Profile | 已有接触与结果的用途 |
| --- | --- | --- |
| 已见开发，N=3 | Goddd / `rpcx-goddd-t3-v1`；Translation / `rpcx-translation-t3-v1`；Workouts / `rpcx-workouts-t3-v1` | 已参与提示/门禁调优及真实生成；旧结果单列，本轮重新生成 |
| 隔离准备后校准，N=1 | GHCLI 有限应用切片 / `rpcx-ghcli-t3-v1` | 准备过程隔离，接入者/参考作者已见内容和对照；五组校准不是五个效果样本 |

拟按表中顺序固定四个 Target，每个仅一次生成、一个原始候选，不自动重试、不人工修复、不以恢复后的最好 Run 替换。Translation 的多个必需构建配置仍算一个 Target。四个均归代码契约的 `development` 分区；报告另存上述方法分层，不新增一个看似 heldout 的 split。

预先纳入的总 N=4，分层 N=3 和 N=1。总表描述这四个固定输入的观察，必须同时给出分层原始计数；不从四个仓库估计任意仓库的生产成功概率。未启动、基线红、超时、预算耗尽等按协议保留在纳入分母。旧真实实验和受控校准不并入本轮分子分母。

独立参考对全部可认证候选执行，不只复核放行项；GHCLI 使用已对齐公开规范的 data-v2，旧 v1 只作历史诊断。实际数据、规范、Profile、参考和工具摘要以新协议发布时的真实字节为准，不直接拿回执说明代替纳入材料。

### 复核如何安排

按用户已委托“其他如果需要复核则由你完成”，本轮采用**助手候选复核**，无需再让用户签相同表格。生成前为各 Target 固定实际 Agent 任务身份与职责，生成后检查 `test_preservation`、`change_coverage`、`delivery_evidence`，记录理由、文件/证据定位、带时区时间及是否参与准备/接入。身份尚未分配，当前不能填成已落实。

复核者不参与本轮候选生成；先按冻结判据独立阅读保存候选，再消费所需验证证据，不向生成 Agent 回送参考答案。准备/接入的既有知识、共享文件系统与同模型家族限制一并披露，不称独立人员或盲审。无法核实的项保持 inconclusive，不自动填 pass。

现有 `candidate_review` 数据结构可记录真实助手身份，它本身不认证人类身份。因此本轮若复用该结构，协议和报告必须明确 `assistant` 方法标签，不能冒用用户署名，也不能把它当成原协议的人类复核已完成。新结果不回填旧实验。有效自动成功/错误放行仍依赖完整参考与复核，未知按[草案指标](../experiments/m5-evaluation-draft.md#计数与指标)报告。

| 条件 | 当前事实 | 冻结前的动作 |

| 新应用正式协议准入 | [protocol.go](../../scenarios/rpcx/l2/round/protocol.go)只允许它进入 schema 1 的 `development_calibration`；schema 2 白名单只有旧三个 Profile | 显式支持新应用的 schema 2 `development`，验证协议绑定与负例；heldout 保持拒绝 |

| 独立参考身份 | 四个输入已有参考；新应用当前发布为 data-v2 | 固定实际参考材料/工具摘要，校验生成前绑定及独立可见范围 |

| 当前实现与环境 | 现有工程包 v0.1.1 是旧版本，不包含随后全部接入变化 | 准入实现完成后导出本轮源码/依赖、构建二进制，固定 Go/OS/镜像 digest、引擎和资源配置；重建/离线核对 |
| 模型、预算与时限 | 旧能力材料及单次授权属于旧实验；本轮数值未冻结 | 固定模型/模式/输出限额、C/O 依据、Q、两级调用/Token 限额、工具/Run/整轮时限与 N/K；核对可准入且上界有依据，不以 Token 充当金额上限 |
| 实际协议与计划绑定 | schema 2 已有材料、后端、计划与预定复核人绑定机制；四任务尚无实际发布材料 | 新版本协议与四份材料落盘后计算真实摘要，离线检查纳入、错配拒绝、汇总和归档；占位 hash 不算通过 |
| 该次外发与消费授权 | 未取得本轮四任务生成授权；旧授权不能续用 | 材料可审阅且预算明确后，最后请求该次外发/消费授权；此前不读密钥或发起模型请求 |
| 原严格未见与人员条件 | 原名额及缺口仍在；本轮的隔离准备/助手复核不满足它 | **不阻止这次明确降限的固定样本评测**，但仍阻止宣布原 M3/M5 总体验收通过 |

`formal_evaluation` 表示按冻结协议纳入并执行的程序约束，不能凭这个 kind 证明样本未见、参考无偏或复核者是人类。现有结构校验也不能证明评审内容真实；报告必须携带实际方法说明。

## 5. 接下来的两个工作单元

1. **让四 Target 可按冻结协议离线准入。** 完成新应用 schema 2 开发分区支持及针对性测试：正确固定身份可纳入，错 Profile/输入/参考/协议/后端/复核人拒绝；heldout、单任务多次尝试、恢复替换原 Run 和未授权的受控模型正式运行仍拒绝。复用既有材料绑定，不引入新 schema、规则 DSL 或开放任意 Profile。这一步的完成证据是离线契约测试，不是新增模型效果。
2. **发布本轮真实冻结材料，再执行一次。** 确定实际复核者、模型能力/预算及最终代码环境，发布新的版本化协议和四任务清单，完成无生成的发布核对；取得新授权后才运行一次批次。保存原始结果、参考/助手复核、指标重算与可搬移归档；生成后不调门禁或参考来美化本轮数字。

停止条件：身份/预算边界不成立就不启动生成；生成中严重偏离停止并保留成本；参考或复核不完整则报告未知，不删除失败或追加生成。若要进一步调优，在本轮封存后另开开发工作，再用新版本协议衡量。
