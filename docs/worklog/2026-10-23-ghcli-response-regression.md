- 目标：将[真实候选中的返回值差异](../experiments/2026-10-23-ghcli-dev-real-model-02.md)从 runs 临时诊断转为随 Git 可运行的开发回归。

## 问题与取舍

真实候选新增了错误时清空响应的分支。CheckRedirect 返回普通错误时，原 invokeHTTP 返回非空响应和错误，候选返回 nil 和错误；这违反规范的返回值保持。原门禁 request_scope 未知并保留 NeedsAttention，但固定自动参考通过。此次先固化可观测反例及正例，不重写历史候选或以新结论覆盖原参考。

| 方案 | 收益与代价 | 选择 |
| --- | --- | --- |
| 在生产门禁中匹配该错误分支 | 能给出直接违规，但 AST 写法可能变化，还需证明新规则不会误拒等价代码 | 当前未知已阻止自动放行，先取得可复用契约再设计生产接入 |
| 给固定参考直接加测试 | 扩展自动覆盖，但原地修改破坏历史版本；新发布还涉及参考身份与接入验收 | 原参考保持，新版本发布另作完整单元 |
| 独立开发回归，存原样来源与正反例，用实际函数验证返回值契约 | 不改变运行策略；只验证这个已见边界，不自动提升判定能力 | 本步采用，优先保证反例可复现、正负对照可区分 |

新包放在 scenarios/rpcx/ghcli/regression，不在父包生产材料的 embed 范围内。测试数据保存原模型 outbound.go 的完整原字节，引用既有公开基线/SDK/规范摘要；从原基线和这份边界源码可复原原候选的完整模块身份，不依赖被忽略的 runs 文件。候选原注释随原文保留，新增测试及执行代码注释采用中文。

本机原生 Go 子进程只执行已审查、固定的开发输入，使用纯内存 RoundTripper，不监听或请求真实 HTTP、无模块下载。不接受任意仓库/模型文件，不把此开发测试当作运行时沙箱。沿用既有数据版本边界，不另建 ADR 或生产执行器。

## 实现与验收计划

基线 v1、原样 v2、仅移除清空分支的 v2 对照，以及故意丢弃错误的 v2 负例，各自放入独立临时模块，使用原发布 SDK。只测试成功响应、传输错误、拒绝重定向时的响应＋错误、ErrUseLastResponse 四种返回值/Body 责任；不声称覆盖超时、任意调用图或完整 CLI 行为。

要求实际 go test -json 的四项测试均运行且有完整终态。原样 v2 只在重定向拒绝项失败；保留响应的对照全通过；丢弃错误的负例必须在错误链项失败。编译错误、panic、超时、跳过或缺事件不能算作反例被捕获。正常 go test 默认运行，不需要 Docker 或 runs；可显式指定全新产物目录保存输入、日志和结果。

完成后运行相关包检查，验证正式门禁和参考工具身份未变、旧材料摘要不变，更新命令和进度并提交。此次没有真实模型请求，不修改冻结数据、既有参考、原候选和历史指标。

## 结论与后续边界

现在可以不依赖旧 runs 重现“原测试/旧参考通过，但返回值契约被破坏”的已见反例，并以两种修改对照确认检查能区分响应丢失与吞错。现有 deleteRelease/deleteTag 调用方先检查错误，因此本轮证明的是 invokeHTTP 的返回值差异，不推断已发生用户可见的 CLI 输出变化。

原门禁仍为 NeedsAttention，原参考仍为 pass，原助手复核仍为 fail；新契约不会自动改变这些结果。保留响应的对照只通过本次四项检查，不证明完整迁移正确，也不计自主迁移成功。未增加模型请求、Token 消费或效果样本。

下一项可单独设计并发布新版独立参考，将响应与错误同时返回、错误链和 Body 责任纳入支持范围；沿用本次正负对照，但如实标为已见开发样本。若后续选择生产门禁接入，应另验证材料绑定、失败与设施错误分类及未知边界，不能仅匹配一个 if 分支就宣布支持。
