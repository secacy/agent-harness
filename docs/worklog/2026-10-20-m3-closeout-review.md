## 1. 评审方法与边界

逐条对应现有七项验收条件，读取历史测试日志、受控 Campaign 汇总、原真实 Campaign/账本/报告、独立参考、复核模板和样本选择清单。历史日志无失败仅说明该次验收结果，不算本轮重新运行测试，也不推断任意未来输入可靠。

本轮不重跑 Agent、模型、候选或 Docker，不改变判定和指标，不填写实际人工复核。仅做证据核对、阻塞项归类和文档推进顺序修正。材料索引和结果位于 runs/m3-closeout-review-01/，不入 Git；这里的脚本不是 M4 通用审计工具。

## 4. 阻塞项与完成条件

### R1：实际人工复核（阻塞 A6）

需要实际复核者对原三个候选分别检查 test_preservation、change_coverage、delivery_evidence，并在新记录中填写身份、时间、理由及文件/证据定位。助手可以整理材料、定位原断言和未知项，但不以 candidate_review 身份代签。

应先看原补丁、规范、原测试和原证据；新 Goddd/Workouts 开发校准可辅助定位，不能替代原工具条件或回写原 Run。尤其 delivery_evidence 必须处理已确认的原六处断链，不能因为当前渲染已修复就填“原交付无问题”。复核不要求所有项 pass：有充分证据确认违规可以 fail，未能判断继续 inconclusive；不能为了收尾强行通过。

完成记录后，以另一个 Request 和全新目录消费原参考及真实复核，再记录结论、局限与仍未知部分。自动成功仍为 0/3，原质量仍为 NeedsAttention。若完整参考仍有未解决 inconclusive，A6 不自动改为已满足。接口及材料要求见[离线参考](../../scenarios/rpcx/l2/evaluation/README.md)和[轮次汇总](../../scenarios/rpcx/l2/round/README.md)。

### R2：实际留出准备与保管（阻塞 A7 / L2 数据准备目标）

用户此前已明确暂不能安排独立准备者；本轮保留待办，不重复要求立即安排。后续需由未参与调优的准备者按已有准入流程完成来源、同源组、许可、离线基线及保管，提供允许开发侧接收的身份摘要与保管元数据，开发侧不读取源码/答案调优。

只有 metadata 名额不等于样本。若需要改变首版是否要求实际留出的范围，应另行明确调整验收约定并保留原因；本评审不把它移到 M5 来宣布 M3 通过，也不由同一开发助手或子代理创建材料冒充未见样本。准入条件见[样本设计](2026-10-19-m3-4-sample-selection.md#6-划分留出与访问边界)。

### 本轮不新增的“阻塞”

Translation 支持范围扩展、让三个候选全放行、将 A=0 改成非零、重跑模型得到更好结果均不是完成本轮复核的必要条件。继续保留有限分析边界和已知未知；不为阶段验收扩大分母或改判。

Harness 进程崩溃恢复、受控重跑、通用审计与恢复后的资源清理仍属 M4，不反过来增加为 M3 必须先实现的功能。
