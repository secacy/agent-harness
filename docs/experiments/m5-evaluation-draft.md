- 依据：[里程碑评测约定](../MILESTONES.md#贯穿各阶段的评测约定)、[M4 收尾与冻结门](../worklog/2026-10-21-m4-closeout-review.md)。

## 问题与适用范围

在固定实现、任务和预算下，衡量公共 rpcx SDK 不兼容升级的自动交付、错误放行、未知结果与成本。机制故障试验、已见开发校准和未见样本效果分别报告，不合并分母；不推断任意 SDK、仓库或供应商上的生产概率。

已有 [l2-dev-eval-v0.1.0](l2-dev-eval-v0.1.0/README.md)是完成的开发实验，不转为 M5。Goddd、Translation、Workouts 均已参与调优，只能作开发回归。留出名额不是样本；实际独立准备者、来源/同源组、保管和访问记录尚缺。本协议草案不新增或查阅留出输入与答案。

## 独立准备与接入交接

当前原独立人员口径下的 `l2-heldout-01` 仍为 awaiting_independent_preparer；实际人员、保管者、宿主接入维护者及未来复核人未指定。此前用户“暂时不能安排”的回答只描述当时条件，不推断为永久不可用。按用户后续提出的方式，已另行启动一个不继承主对话的新 Agent 做隔离准备试点，见下节；它可承担实际准备工作，但不充当独立真人。下表保留原角色要求，不构成运行授权。

| 角色 | 实际工作与边界 |
| --- | --- |
| 独立准备者/保管者 | 未参与提示或门禁调优；选择来源、裁剪并植入基线、保存原测试映射、依赖和许可，独立保管完整输入/参考及访问记录；可按预定流程检查环境，不能凭迁移成功与否筛选样本 |
| 可信宿主接入维护者 | 认证数据、Profile 和全部配置，检查正确/违规/未知对照及 Agent/门禁可见根；实际由谁承担、是否接触答案和是否参与全局调优，须在接触前约定并记录 |
| 正式候选复核人 | 在生成前固定身份及三项判据，生成后实际检查保存候选与证据；如兼任准备者，披露既有知识与角色关系，不声称独立盲审；助手辅助不替代实际签署 |
| Harness 调优开发侧 | 固定模型适配、提示、工具与通用规则；开发期间只接收允许的元数据，不读取留出源码/答案/结果调优 |

准备与接入按以下顺序进行，不能先把完整仓库发到当前开发工作区，再补一份“未见”声明：

1. **先交接允许的元数据。** 至少列任务标识、来源仓库/固定版本与同源组、许可、材料版本及实际摘要、准备者/保管者与角色关系、基线环境要求和访问记录所在位置。初次尚未生成的摘要如实标为未准备，不填写假值；此时不算数据已验收。不得选择 [surveyed_sources](../../scenarios/rpcx/l2/selection-v0.1.0.json) 中已查阅的来源或其同源派生工程充作严格未见样本。只接收身份/环境元数据不等于打开源码，但仍记录接收与后续访问。
2. **由准备者保管并验证完整材料。** 保留上游 U→可离线、植入 rpcx-v1 的基线 B 的逐文件映射、原测试/断言保留和裁剪说明、依赖闭包与许可、全部必需配置的禁网基线命令/测试事件及摘要。30 秒约束列为植入语义。先冻结 B，再制作正确/明确违规/无法充分验证的对照和独立参考；不得从正确迁移补丁反向构造基线。失败或改选记录保留，环境不适配和基线红不算迁移结果。
3. **在开放内容前约定宿主接入。** 当前 v2 硬性拒绝 heldout，现有三个 Profile 也认证固定基线；不能给新目录套旧 ID，或只放开 split 就运行。需要实际数据发布、宿主 Profile、运行时检查、独立参考、全部配置和正反例的接入证据；设计与实现应作为有实际材料可验证的独立工作。若由独立维护者在隔离环境接入，记录其改动范围及未修改的全局组件，实际执行时固定完整实现；这个过程当前尚未实现或验收。
4. **记录接入导致的暴露。** 若必须让当前调优开发者/助手读取留出源码或答案来实现 Profile/修改规则，先登记开放原因、对象、时间和范围；该版本按已见开发或固定外部验证用途另行声明，不能继续填补原严格未见条件。普通源码 hash 和 `independent=true` 字段都不能证明独立性。禁止自动扫描保管目录或把隐藏答案纳入全量测试。
5. **齐备后才冻结和运行。** 任务材料、宿主支持、参考、人员及全部执行/预算条件齐备后，按下文冻结门发布实际协议，再取得该次外发/开销授权。执行时向 Agent 提供任务所需输入，oracle/expected/参考仍在 Agent 与门禁之外；正式结果未开放给开发侧调优前保留访问记录。缺一项就保留待准备，不用额外模型调用替代准备工作。

完整材料至少分开保管：原来源与基线/依赖包、宿主验证/Profile 材料、独立 oracle/对照与预期、环境/基线证据、角色与访问记录。逐文件摘要固定真实字节，来源说明和“独立”声明仍由实际人员负责；无人工活动计时则保持审核耗时未知。元数据接收、基线复验、宿主支持和正式冻结分别记录，互不替代。

原独立人员安排尚未落实时，不宣称该口径已满足；Agent 准备方案另行记录，不将“当时无人接手”视为永久禁止其他准备方式。当前正式交付结论仍基于已见开发集与工程证据，M5 未冻结、未启动。本节是准备交接说明，不是新增样本、已签署人员安排或可执行 batch 配置。依据、取舍与核对见[本步记录](../worklog/2026-10-21-m5-intake-handoff.md)。

## Agent 隔离准备试点

全新 Agent 可以作为另一种准备安排：本轮使用独立对话、`fork_turns=none`，只提供通用迁移契约、共用 SDK、冻结实现与已见来源排除清单。新来源完整材料在单独的忽略目录保管，当前调优流程只接收元数据及准备状态；不把源码、oracle、补丁或详细日志回传给主 Agent。实际任务、目录与结果见[试点记录](../worklog/2026-10-21-agent-isolated-preparation.md)。

首阶段已有实际 prepared_baseline 回报，公开回执见 [agent-preparation-v0.1.0](../../scenarios/rpcx/l2/agent-preparation-v0.1.0.json)：一个库级协议切片禁网构建及所选 54 项测试/子测试通过，一个外部服务测试套件保留未执行；主流程未打开完整材料或独立重跑。该回执时点尚未评估应用业务代表性与 L2 准入，未注册 Profile，不能据此宣布原留出准备完成。

随后 [准入评审](../../scenarios/rpcx/l2/agent-admission-v0.1.0.json)将该版本记为 supplementary_only：应用/领域代表性及出站适配保真不符合预定条件，部分相关覆盖与运行契约仍未知。原基线验证事实保持，当前不进入 L2 业务样本的参考/Profile 开发，不计作正式评测结果。再次准备应用样本应先检查这些选源条件，不能等基线完成后才发现范围不适配。

[后续应用选源](../../scenarios/rpcx/l2/agent-application-selection-v0.1.0.json)按上述条件固定一个不同源业务切片的 U 和适配计划，记录当时的 selected_not_prepared。该回执时点尚无 B、构建/测试未执行、迁移相关性与离线可用性未验证；静态资格只是后续基线准备输入，不能算完整准入或新的实验结果。

该固定来源另存[应用基线准备回执](../../scenarios/rpcx/l2/agent-application-baseline-v0.1.0.json)：prepared_baseline，准备者禁网构建、原测试及新增/v1 SDK 检查通过；原测试覆盖观测支持其确经实际适配生产路径。主流程未读取私有材料或重跑；有限基线不能代表整个上游、v2 迁移或正式效果。旧选源/准备回执保留原时点状态，独立准入结果另存。

[应用准入决定](../../scenarios/rpcx/l2/agent-application-admission-v0.1.0.json)为 admit_for_reference_preparation：新隔离评审者只读比较来源/基线并核对存量证据，六项必需条件均 supported，输入未改、测试未重跑。当前可推进独立参考与有限正反例准备；完整默认期限真实到期等尚需后续建立，可信 Profile、正式协议冻结与原人员留出条件均未由本次准入满足，不自动纳入原效果分母。

方法标签为 fresh_agent_preparation。它隔离的是当前开发上下文与准备过程，不是独立人员、不同模型家族或独立权限系统；基础模型是否在训练中见过公开来源无法据此证明。本轮先检查新样本的基线准备可行性，原严格人员留出要求及原选择清单保持，不在正式实验中悄悄换口径。

若试点进入后续实验，须在新协议中固定实际准备身份、允许可见范围、完整数据/Profile/参考及角色，并明确采用的隔离强度；主流程因接入需要打开源码或答案时，按前述暴露规则记录。当前 v2 的 heldout 校验仍关闭，准备成功也不自动获得正式纳入或付费调用权限。

## 拟采用的实验规则

正式发布时须把下表的待定项换成真实清单和数值。发布后有实质变更即新版本，原失败和偏离记录保留；不能在看到结果后换样本、调预算或挑最好 Run。

| 项目 | 拟定规则 / 冻结所需材料 |
| --- | --- |
| L1 机制回归 | 固定任务 manifest 和 expected、规范条款、实现身份；逐 case 检查 verdict 与证据引用。输出构造集计数，不用其人为错误比例估计真实放行风险 |
| L2 开发回归 | 固定三个已见来源的实际数据版本、Profile、全部必需配置及独立参考；与留出分表，不以旧校准替代本次运行 |
| L2 正式留出 | 沿用 M3 同源分组原则；准备者单独保管。实际来源/版本/摘要、样本数量和基线检查流程待齐备，未齐备不得冻结 |
| 次数与候选选择 | 拟每 Target 一次正式生成尝试、一次候选；重复次数为 1，不宣称统计稳定性。未启动、基线红、超时、预算耗尽、非法回复、设施失败均在已纳入 N 内，列原因 |
| 重试与恢复 | 正式效果轮不自动重试、不人工修复、不更换原候选；M4 恢复单列确定性故障实验。正式生成中断后保留状态/占用和失败，不拿恢复后最好 Run 顶替；如需评估多次尝试，另起协议并先实现对应多 Run 汇总 |
| Agent 与门禁 | 固定提示/工具/预算提示、模型适配、门禁和 Profile；每 Run 独立对话。Agent 仅见本任务必要输入；oracle、expected、参考、其他任务和账本不进入可见根；门禁不读取 oracle |
| 模型与预算 | provider/endpoint/model、模式、max_tokens、C/O 来源、单请求 Q、两级调用/Token 上限、工具/Run/整轮时限和 N/K 全部待实际冻结；不沿用旧单次授权、不以 Token 冒充金额账单上限 |
| 环境 | 完整源码与依赖、二进制、Go/OS/架构、镜像 digest、Docker context/engine、资源限额、网络/挂载/缓存规则及原生命令；不能只固定未包含工作区修改的 HEAD |
| 纳入与发布 | 生成前绑定任务顺序/输入/规范/Profile/参考/工具及协议摘要；保存实际 Plan 后、接纳前发布动态纳入材料。能力或材料不符合冻结值时零生成停止，不临时放宽 |

目前 [v2 协议契约](../../scenarios/rpcx/l2/round/README.md#v2-协议契约)已接入 formal_evaluation：生成前绑定计划设置、实际后端、四份材料与预定复核人，离线重查发布副本；开发夹具及本机模拟服务验证机制，不计本轮正式结果。当前仍只支持三个既有 L2 Profile 和 development 分区；未接入的 heldout 明确拒绝。实际留出及认证、完整材料与角色尚需落实，不能靠新字符串或合成材料通过 M5 验收。本草案不是 CLI 配置格式，不提供不可运行的命令。

## 独立参考与复核

对所有可认证候选运行独立参考，包括 Rejected 和 NeedsAttention；无法取得完整候选时保留不可评原因。固定参考数据/工具、执行参数、必需配置、事件和计时容差，不因新候选失败放宽。

自动结果为 pass / fail / inconclusive：候选确定违反规范才能记语义 fail；参考编译不适配、设施失败、缺事件或不足证据保持未知。自动 pass 后仍须按冻结人员安排实际复核 test_preservation、change_coverage、delivery_evidence，记录身份、带时区时间、材料定位、理由及与开发调优的关系。助手可辅助，不能代替实际人签署或声称盲审；缺复核保留未知，不补写 pass。

迁移/测试错误和交付依据错误分别计数，同一候选在总错误数只计一次。完整参考 pass 也不能把原 NeedsAttention 改为 ReadyForReview。若正式结果被用于调优，该样本此后转为开发用途，不能在新轮继续声称未见。

## 计数与指标

每个 split 单独统计。N 是生成前纳入 Target 数，R 是实际 Run 数，Q 是获得原质量判定数，A 是 ReadyForReview 数，H 是 NeedsAttention 数。没有生成候选不从 N 删除；配置在接纳前非法时保留拒绝记录，不虚构一轮有效比例。Translation 多构建配置仍是同一个 Target。

| 指标 | 定义与未知处理 |
| --- | --- |
| 有效自动成功 | S 为原 Run Completed、ReadyForReview 且完整独立参考 pass 的数量，报告 S/N。放行但参考未知的潜在成功数 u_s 单列，必要时报告 [S/N,(S+u_s)/N]，不把下界当完整成功率 |
| 错误放行 | k 为放行候选中完整参考确认错误数，u 为放行后未知数；A=0 无定义，不能填 0%。A>0 且 u=0 报 k/A，否则只报 k/u/A 和 [k/A,(k+u)/A]；该范围不是统计置信区间 |
| 人工确认 | 同时报 H/N 和 H/Q；Q=0 时后者无定义。另列执行失败、未启动及无判定，不将此比例称为人工耗时 |
| 成本 | Campaign 总账只计一次；分列各 Target/Run、准入/拒绝、Loop 尝试/工具调用、实际已知输入/输出、未知保守占用和在途预留、墙钟/验证耗时。未知不填零；金额和实际人工活动时间无证据时保持未知 |
| 故障与质量分布 | 统计配置/基线、API/协议、预算、工具、设施、中断、发布故障；执行 Failed 与质量 Rejected/NeedsAttention 分列。构造故障不进入正常效果分母 |

身份或摘要冲突使该轮无效，保留诊断与成本；不得发布有效效果比例。参考未完成使相关结果未知，不把它混同整轮身份无效。小样本只说明观察到的个案，零错误不等于普遍无错误。

## 冻结、执行和复核交付

正式冻结需同时具备：不可变协议版本；实际样本/split 与保管记录；逐任务输入/规范/Profile/参考/工具；完整实现/二进制/环境；模型能力与所有预算/时限数值；一次尝试和复核规则；可用且验证过的正式纳入/汇总链路。逐文件摘要清单不包含自身，不能填占位摘要或只附名额。当前均以[冻结门表](../worklog/2026-10-21-m4-closeout-review.md#4-正式评测的冻结门)记录，不标 frozen。

材料固定并获该次外发/开销授权后才运行生成；先记录协议与实际 Plan 绑定，再接纳任务。中断、协议偏离和所有失败单独保存；严重身份/预算偏离停止，不事后重写原记录。M4 工程缺口未闭环前，不宣布 M5 正式启动。

交付包含原始计划/账本/所有 Run、补丁/候选/规范/日志、门禁、参考和复核、汇总原始计数及失败分布、源码/环境重建说明与逐文件摘要。密钥不入包。由他人按归档重算指标、复验保存候选和审计记录，不承诺重新请求模型得到相同补丁。仅交付指向本机 runs 的索引不算完整归档。

若独立准备条件始终不具备，可交付已见开发集报告及工程证据；那是带局限的开发版，不能以更名代替原 M3/M5 的留出与正式效果验收。
