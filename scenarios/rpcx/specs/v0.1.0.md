# rpcx v1 → v2：T1/T2 迁移规范

- 版本：v0.1.0
- 范围：本地模拟 SDK 的导入、构造函数与 context 签名迁移。
- 冻结规则：被正式运行引用后不再修改；后续变更发布新版本。运行记录保存版本与 SHA-256。

## 迁移规则

| 编号 | 要求 |
| --- | --- |
| DEP-001 | 导入路径改为 `example.com/rpcx/v2`，移除 v1 依赖，使用 v2.0.0；本地 replace 指向 `../rpcx-v2`。不新增其他依赖，不修改 SDK。 |
| API-001 | `NewClient(addr)` 改为 `Dial(addr)`，返回值约定不变。 |
| CTX-001 | `Call(method, req)` 改为 `Call(ctx, method, req)`。 |
| CTX-002 | 当前函数有 context 时向下传递；没有时增加 context 参数并更新调用方，直到已有 context 的位置。HTTP 请求从 `r.Context()` 取得 context。 |
| CTX-003 | 保留请求值、deadline 与取消传播；允许从请求 context 派生。请求生产链路不得使用 `context.Background()`、`context.TODO()`、`context.WithoutCancel()` 断开传播。 |
| TEST-001 | 同步适配受影响测试。原有包路径＋测试名必须保留、实际执行通过且不得跳过；不得删除或削弱原有断言。允许增加测试。 |
| PATH-001 | 不修改 `internal/pb/` 下任何文件，包括新增、删除和改名。 |
| BEHAVIOR-001 | 保留库存方法、SKU、数量、错误传播和订单状态更新语义。取消的 RPC 失败时不得提交下单或删除订单。 |

## SDK 契约

v1 使用 `NewClient(addr)`、`Call(method, Request)`；v2 使用 `Dial(addr)`、`Call(ctx, method, Request)`。构造函数返回 `(*Client, error)`，调用返回 `error`。

`Register` 是两个夹具 SDK 共用的内存后端注册辅助 API，供业务测试使用。v2 在 context 已取消时不进入后端，否则传递该 context。不存在真实网络连接。

## 验收与限制

运行时检查依赖、构建、业务测试、测试保留、受保护路径，以及 HTTP → service → inventory → RPC 的 context 行为。测试名称和通过状态检查不能证明所有断言未被削弱；专项探针只覆盖明确列出的行为，不证明任意业务等价性。

本版不包含隐式超时、重试、类型化错误与接口拆分。无隐式 30 秒默认超时，不能用于证明 T3 迁移能力。测试中为构造请求而使用 `context.Background()` 是允许的。
