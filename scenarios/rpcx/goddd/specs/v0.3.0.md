# rpcx v1 → v2：Goddd 货运路线迁移

- 版本：v0.3.0；仅适用 rpcx-l2-goddd-v1 中的 goddd 和 rpcx-l2-sdk-v1。
- 迁移对象为已准备的业务切片，不涉及上游完整服务部署。规范使用后不原地修改。

| 条款 | 要求 |
| --- | --- |
| DEP-001 | 依赖改为 example.com/rpcx/v2 v2.0.0，replace 指向 ../rpcx-v2；移除 v1 require/replace，保留其他模块、版本、go 指令和依赖校验和。不修改 SDK 或宿主离线依赖材料。 |
| API-001 | rpcx 导入改为 example.com/rpcx/v2，NewClient 改 Dial，Call 变为 Call(ctx, method, request, response)。保留请求和响应类型约定。 |
| CTX-001 | 路线查询从 HTTP requestRoutes 经 booking Service、日志/指标装饰器及 RoutingService 传递 ctx；没有请求 ctx 参数的受影响方法、接口、调用者和测试同步适配。 |
| CTX-002 | 请求上下文来自 r.Context()，可在临近实际 RPC 处派生；构造器保存的长期 Context 不能代替本次请求。其他 HTTP 处理函数仅用于错误编码的既有 Background 不属于本次 RPC 链路，但不得将其接入路线查询。 |
| CTX-003 | 请求值、取消和更早的 deadline 必须保留；RPC 生产链路不得以 Background、TODO、WithoutCancel 或构造时上下文兜底。已取消或过期请求不进入后端。 |
| TIME-001 | 为每次实际 RPC 显式恢复 30 秒上限，从 routing 准备该次调用时计时，不跨次复用。 |
| TIME-002 | 有效期限取父 deadline 和本次调用开始后 30 秒的较早者；不延长较短期限，不缩短为未经批准的其他默认值。 |
| TIME-003 | RPC 返回后释放派生上下文资源，不提前取消、不取消父上下文、不复用失效上下文。SDK 为协作式取消，不强制终止忽略 ctx 的后端。 |
| BEHAVIOR-001 | 保留 fetch_routes、From/To 映射、响应各路线/航段/地点/航次/时间字段及顺序；未知货物不发 RPC；远端错误仍转换为非 nil 空路线，空成功响应仍保持原语义。HTTP 仍以既有 200/空路线呈现这些情况，不擅自新增 error 返回 API、错误状态或回滚保证。 |
| TEST-001 | 保留全部 22 个基线测试及子测试的身份、原断言和 helper 逻辑，实际执行且不跳过；允许导入、构造/API 与 ctx 参数适配及新增测试，不允许用删测或削弱断言完成迁移。 |
| PATH-001 | LICENSE 和 go.sum 的内容及路径不变，禁止删改或重命名。原 SDK 与宿主执行材料也保持不变。 |
| BUILD-001 | 默认构建配置下业务模块可构建，所有基线业务测试可编译和通过。 |
| SCOPE-001 | 审核材料声明构建配置、检查路径、工具与材料身份、实际行为证据及未知范围。超出有限结构证明范围的改写需人工确认，行为探针通过不能抹掉结构缺口。 |

v1 内部提供的 30 秒是本地 SDK 植入条件；迁移同时恢复此上限并新增请求 ctx 传播，不宣称原上游服务已有这些契约。迁移约束行为，等价重构可以交付 NeedsAttention，不要求候选与某份参考补丁字节相同。构造器签名可保留兼容参数，但该参数不得成为 RPC 的请求上下文来源。
