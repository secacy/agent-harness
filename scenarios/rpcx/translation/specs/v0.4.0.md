# rpcx v1 → v2：Translation 双配置迁移

- 版本 v0.4.0；适用 rpcx-l2-translation-v1 与共用 rpcx-l2-sdk-v1。发布使用后不原地修改。

| 条款 | 要求 |
| --- | --- |
| DEP-001 | require 改 example.com/rpcx/v2 v2.0.0，replace 指向 ../rpcx-v2，移除 v1 require/replace；保留其他依赖版本、Go 1.26.0、go.sum 及只读 SDK/宿主材料。 |
| API-001 | 两种实现导入 example.com/rpcx/v2，NewClient 改 Dial，Call 增加 ctx 第一参数；保留 translate 方法、请求和响应含义。 |
| BUILD-001 | default 与 rpcx_alternate 是同一候选的两个必需配置。分别构建、完整测试、分析和行为验证；默认选 translation_google.go，alternate 选 translation_rpcx_alternate.go。不得删配置、改标签、将两实现合并为唯一调用点或只检验默认配置。 |
| CTX-001 | 原 usecase、tracing 和 WebAPI 已有 ctx，继续传递当前请求上下文；保留 ctx.Err 的提前返回，不用 Background、TODO、WithoutCancel 或长期保存的 ctx 兜底。请求值、父取消和更早 deadline 到达 RPC；已取消/过期请求不调用后端或 Store。 |
| TIME-001 | 两配置的每次实际 RPC 都恢复调用前开始计时的 30 秒上限，不跨次复用。有效 deadline 取父 deadline 和当前 30 秒的较早者，不改成其他默认值。 |
| TIME-002 | 调用返回后释放派生 ctx，不提前取消、不取消父 ctx、不复用失效 ctx。SDK 为协作式取消，不强制终止不响应 ctx 的后端。 |
| BEHAVIOR-001 | 保留 Original/Source/Destination 请求字段及 Translation 结果映射，其他实体字段和用户 ID 不变；远端成功后才 Store，远端/前置取消错误不 Store，Store 错误保留原错误链和零结果。错误用 %w 可解包；不声称具备远端/本地事务回滚。两层 tracing 包装与 History 业务保留。 |
| TEST-001 | 每配置保留全部 26 个基线测试/子测试身份、断言、表数据和 helper，真实执行且不跳过；允许必要 API/导入适配及新增测试，不得通过删除、修改 mock 或削弱断言获得通过。 |
| PATH-001 | LICENSE、go.sum、internal/usecase/mocks_repo_test.go 原路径与内容保持不变；生成 mock 必须实际参与原测试。SDK 与宿主依赖不得修改。 |
| SCOPE-001 | 审核材料分别列明配置、活动源文件、规范/输入/工具身份、实际证据和未证明范围；所有必需证据通过才可常规审核。等价但超出有限结构证明范围的改写标 NeedsAttention，行为探针通过不能抹掉缺口。 |

两个标签实现、内存传输及 v1 的 30 秒默认语义是评测准备植入条件，不代表上游原项目自然具有此迁移。基线原 mock 测试绕过真实传输，其通过不能证明以上 ctx/期限条件。两个配置仍只计一个任务和一份候选。
