# RPCX application migration v0.6.0

Migrate the supplied ghcli business module from example.com/rpcx v1 to example.com/rpcx/v2 v2.0.0 using the supplied sibling rpcx-v2 module. Replace the v1 import and client construction with the v2 Dial interface; all RPC calls must use the v2 context-bearing Call interface. Update the required local module dependency/replacement for this layout.

Each outbound operation has an available parent context on its original HTTP request. Preserve cancellation and any shorter parent deadline. Each individual RPC call must have an explicit maximum duration of 30 seconds, including when the parent has no deadline or has a later deadline. The v2 SDK supplies no implicit timeout. Do not substitute an unrelated background context.

Preserve existing request construction, URL, method, headers and body, operation ordering, branch behavior, returned results and errors, HTTP status handling, and observable application output. The response and its body remain owned by the existing caller. Do not cancel an in-flight response body merely because dispatch returned; preserve body reads and Close errors, and release derived context resources on transport error, absent body, or body Close as appropriate. Existing shorter parent cancellation must remain effective while the caller consumes the body.

Only change the business RPC integration and necessary module metadata. All original tests, go.sum, LICENSE, supporting application packages, both sibling SDK modules, and this specification are protected. Do not edit test assertions, add replacement behavior, remove supporting sources, modify SDK implementation, or fetch dependencies. Use only the published read-only module cache. Preserve the existing in-process transport boundary and its limitations; wire protocol or real network equivalence is not required.
