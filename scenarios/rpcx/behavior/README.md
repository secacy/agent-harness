# rpcx 可信运行时行为检查

`Run(ctx, Request)` 接受冻结基线、候选模块、可信 v2 SDK、空证据目录和显式 execution 后端。当前仅支持 T3 v0.2.0 夹具；原测试由 testintegrity.AdaptBaseline 认证并适配，SDK 生产文件由固定摘要认证。它不读取公开补丁、cases 预期或 oracle。

宿主保存三个完整输入快照，将候选所有非 `_test.go` 文件原样装配为 demo-orders，剥离所有候选测试，再安装三份适配后的原测试和独立编写的行为探针。生产文件摘要逐项保留；候选测试中的 TestMain/init/helper 不进入执行副本。生产初始化仍然会执行，缺失测试事件或异常退出不能当作通过。

先运行快速阶段，通过后再运行真实 30 秒到期阶段：

| 范围 | 必需叶子测试 | 检查内容 |
| --- | --- | --- |
| 原业务测试 | 10 | 原包和名称的实际执行结果 |
| Reserve / Release | 16 | 每次 30 秒期限、较早父期限、元数据、预先取消/过期、运行中取消、资源释放、错误和重复调用 |
| Place / Cancel | 6 | 已取消、过期及后端错误通过 errors.Is 可识别；失败不错误更新订单 |
| HTTP Place / Cancel | 6 | 请求值和取消穿过 handler/service/inventory；状态码、RPC 次数和参数 |
| Place / Cancel 真实到期 | 2 | 两个协作式后端并行等待真实 30 秒取消，核对错误、调用次数及订单状态 |

总计 40 个必需叶子测试。快速阶段未通过时，两个慢检查记录为 not_run。期限观察区间超过 250ms 时跳过对应测试并保留 unknown；不扩大容差来得到通过。慢检查后端最多观察 34 秒，Go 测试进程另有 50 秒上限；调用方还应提供有界 context。

报告 schema_version=1，状态为 pass/fail/unknown，与最终质量 verdict 分开：

- 每项要求唯一 run 和终结事件；pass 还要求所在包有结束事件。跳过、缺失、重复、非法事件、构建失败或 panic 均不能通过。
- 可以明确归因到已执行测试的失败记为 fail；其他未完成记录为 unknown。fail 优先，仍保留所有缺口。
- 后端错误、取消、OOM、输出超限、源文件或装配副本变化返回 error 和空 Report，保留原始日志，不保留 report.json。

证据目录保存 `inputs/` 原始快照、`materials/` 探针与实现及适配记录、`trusted/` 实际装配文件、两个阶段的原始 go test JSON/标准错误/执行元数据和 `report.json`。报告分别绑定完整输入、候选生产文件、装配集合和材料集合。适配记录还绑定 testintegrity 实现摘要与宿主 Go 版本。每个阶段前后核验装配内容，阶段前及返回前核验原输入。

真实 Docker 使用固定镜像和既有资源限制，两个模块只读挂载；Local 只供可信开发夹具使用。各阶段为新进程，生产字节相同但内存状态不继承。不复制参考检查文本；生产探针和独立 oracle 分别维护，以后通过 L1 矩阵比较结果，不能用本探针替代评测参考标准。

**边界：**这是有限的默认构建配置和列明调用路径的行为证据。规则引用说明测试涉及的条款，不表示单个测试证明整条规范。它不证明任意生产代码无恶意、不覆盖其他 tag/平台/输入，不证明原断言保留，不输出 ReadyForReview。安装的 SDK 字节经过认证，但实际模块解析还依赖候选 go.mod；调用方必须另行验证 DEP-001，不能用行为通过替代依赖检查。[T3 组合门禁](../checks/README.md)已将这些结果与依赖、候选测试、结构和分析检查组合；Runner 的新规范选择仍待实现。
