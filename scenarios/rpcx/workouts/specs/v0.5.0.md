# rpcx Workouts 取消切片迁移规范 v0.5.0

适用输入为 rpcx-l2-workouts-v1：trainings 业务模块、只读 common 本地模块及 rpcx-l2-sdk-v1。仅覆盖取消路径，不承诺原整仓 Firestore、gRPC、Schedule/Move 或跨远端事务。发布后不原地修改。

| 条款 | 验收条件 |
| --- | --- |
| DEP-001 | trainings 的 rpcx require 更新为 example.com/rpcx/v2 v2.0.0，删除 v1 replace，保留已有 v2/common replace、第三方依赖版本与 go.sum；SDK 与 common 的内容不变 |
| API-001 | 导入 example.com/rpcx/v2；NewClient 改 Dial；两个 Call 的第一参数为本次调用 ctx，保留方法名、用户/余额/训练时刻和空确认映射 |
| CTX-001 | Handle 的 ctx 传入 UpdateTraining；仓储给 update callback 的 ctx 才是 callback 内两次出站调用的来源。保持其值、取消和较短期限；不得捕获外层 ctx 代替回调参数，不得以 Background/TODO/WithoutCancel 兜底 |
| TIME-001 | UpdateTrainingBalance 与 CancelTraining 每次调用分别从实际 ctx 派生不超过 30 秒的期限，无较短父期限时为 30 秒；不得将整个 Handle 共用 30 秒冒充逐调用期限。派生后实际传给 RPC，取消/到期应结束等待 |
| TIME-002 | 采用 context.WithTimeout(ctx, 30*time.Second) 并 defer cancel() 是已支持形式。正常和错误返回都释放派生 ctx，不取消调用方；重复调用各自重新派生 |
| BEHAVIOR-001 | 保留原取消规则、零余额跳过 users、余额→trainer 顺序、参数/确认、原错误包装及 errors.Is 链。取消或远端错误时 callback 不返回可提交成功；成功才提交本地训练状态。trainer 失败不抹去此前成功的余额远端副作用；不引入隐式重试、补偿或回滚 |
| PATH-001 | 不修改 LICENSE、go.sum、common 与两个 SDK；原领域和 command 的业务行为必须保留 |
| TEST-001 | 保留所有原测试名称、表数据、断言与通过状态，允许 rpcx 导入/API 必要适配；禁止删断言、跳过、空成功或改预期遮蔽失败。common 三项测试也必须实际执行 |
| BUILD-001 | 固定 default 配置，common 和 trainings 分别构建、完整测试成功；证据缺失不能当作通过 |
| SCOPE-001 | 门禁只证明发布切片的有限生产结构、两个类型身份 RPC 对应与实际探针所覆盖的契约。新增 helper/控制流等无法证明的变化须 NeedsAttention；明确违反条款为 Rejected；执行设施/认证基线失败没有候选质量结论 |

Agent 可读取业务工作区、规范、common 和两个 SDK，只能编辑 trainings 中未保护文件。可信测试与探针由宿主提供，不读取候选中的评测预期。交付为补丁与审核证据，不自动合并。
